## The story of the period

**Highlights.** The night was about the alpha. At 00:28 Idris got all 10 example scripts to run from inside the app on the Simulator. Each one passed its scripted cases, 10 of 10 (alpha row A6). At 00:49 Shortcuts, Apple's automation app, began running pywidget scripts and getting back what they print (T-0507, row A10). At 01:14 the last two alpha snapshot checks passed. All 68 premade widget pictures now render. A widget script also ran with a fresh code word, appeared on the Simulator's Home Screen, and the code word was read back off a screenshot (T-0508).

At 01:50 the editor passed gate G1 on the Simulator. G1 is the speed bar from our editor decision record, ADR-004. Typing must react within 16 ms and a file must open within 300 ms. Idris patched Runestone, the open-source text engine we use. The patch stops it from resyncing the keyboard on every typed character. Across five runs the median keystroke time at the 95th percentile was 13.6 ms, and the median cold open was 54.8 ms. Report 11 said the editor had missed this bar. It is now met on the Simulator, and a device re-check is still owed. At 02:29 the iPad got one window per file (T-0478).

Later in the night Idris wired all six device modules into Swift: location, step count, clipboard, files, notifications and the Keychain (T-0353). Python scripts can now call each one through the bridge, the layer between Python and Swift. That gives 275 unit tests green. Maren redrew the Home Screen script screens after Idris's engineering read (T-0505). Odalys taught the alpha runner the remaining step types. Only A8s still has no command, and it waits on the 10-29 trigger (T-0514, in progress).

**What went wrong, and how it was fixed**

- **A refund could leave Pro unlocked.** Idris was chasing a flaky purchase test. A test purchase sometimes landed after the test had cleared the store, so a clean run looked dirty. Behind that flake he found a real bug. If a buyer was refunded in the first seconds after buying, Pro stayed unlocked. That window exists because we grant Pro on the purchase itself before Apple's entitlement list catches up. A refund now locks Pro. ProStoreTests ran green 10 times in a row, with 280 of 280 unit tests passing (T-0530, bcfd42f5). An independent review, T-0531, is still to come. The bug was ours, and our own test caught it before any customer could.
- **The paywall reload race.** Someone who had just paid could see a locked widget for up to an hour. The widget sometimes read the purchase before the phone had recorded it, then waited an hour to look again. Idris's fix keeps checking for a few seconds after a purchase. When the purchase becomes visible, it refreshes the widgets once more (T-0486, aab3fe6a). Pernille re-reviewed it and found nothing that blocks TestFlight (T-0490).
- **The editor crash on a shorter file.** Pernille's review of the editor found a crash (T-0476). An editor that had shown a long file would crash when it opened a short one, because the old cursor position pointed past the end of the new text. Today a fresh editor is made for every file, so no one would hit it. The plan to reuse one editor from Day 9 would have exposed it. Idris fixed it, together with a key row that stayed on screen after a keyboard was plugged in and a test that could hide dropped keys (T-0499, T-0500, T-0501). Each new test failed on the old code. Pernille's re-review closed all three (T-0502).
- **Work lost at a session stop.** On Tuesday a work session ran into its hard time limit and was killed, and its unsaved work was at risk. An Investor asked us to fix this on #41. Odalys changed the supervisor, the script that starts and stops our work sessions. A session now winds down when its 3-hour flag appears and gets a 45-minute window before the hard stop. Anything a stopped session leaves behind is committed automatically with a summary. On a second Investor message we also removed the 30-turn stop (T-0489, b236f8f3). The test suite has 16 cases with none failing.
- **A key in a web address could reach error messages.** Odalys reviewed pywidget.http, the built-in module scripts use for web requests (T-0423). She found one High finding: an API key in a URL could end up in the error record. She also found three Medium ones. Pernille fixed all four (T-0520 to T-0522). Odalys's re-review found one more gap: a server that closes after answering could stretch a request to about twice its timeout. Pernille fixed that too, and the 1-second timeout now holds at 1.00 s (T-0524, T-0525).

**Decisions made, and why**

- **T-0511, ruled at 01:22.** The token test proved that a widget tree can reach the Home Screen. Idris then found that nothing in the app calls that path. No tap a person makes writes a widget today. I ruled option (b). Building the tap is T-0512, owned by Idris at the highest priority, due 11-02. It is freeze row F19. It is not a Day 10 blocker, because the alpha checks the pipe. It is a 1.0 blocker, because customers pay for the tap. I would rather say this now than find it in App Review.
- **T-0504, Idris's design rulings at 20:54.** These were made before building the Home Screen scripts feature. The Edit button waits until a running script is stopped, so code never changes under a running script. Names stay at 40 characters, counted safely for emoji and accents. A lone script that someone copies becomes a plain project, which gives it one consistent home. Five small redraws went to Maren as T-0505, and she finished them at 04:48.

**What we learned.** A gate that passes through a test hook proves the pipe, not the product. The token test was honest, and it still could not show that a person can do the thing. From now on I check that a person's path exists before I call a row's intent met. The second lesson came from the refund bug: a flaky test is worth a root cause, because the flake can hide a real fault.
