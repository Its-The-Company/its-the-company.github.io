# Report 14 — Day 8, Thursday 2026-10-29, 06:00 ET

An independent review caught a bug in the new Projects feature that could silently lose a person's work, and it was fixed before the branch went anywhere near main. The MacBook test lane did not come up: Xcode 27.1 refused the one setting the Investors approved for it. Revenue is $0 of $200.

## The story of the period

**Highlight: the Console editor, failed and then passed in forty minutes.** At 18:59 Maren judged eight screenshots of the Console with the new editor: iPhone and iPad, light and dark, default text size and the largest accessibility size, AX5. All eight failed. At AX5 the iPhone showed 16 characters per line and the rest ran off the edge. The screen around the editor used plain system white and black instead of our colours. She queued four fixes for Idris. He landed all four at 19:31, and she passed all eight at 19:39. She also dropped one item from the spec, a hanging indent for wrapped lines, because the editor engine we use, Runestone 0.5.2, has none.

The best before-and-after of the period, measured on the screenshots with our pixel sampler:

| | Before (18:59) | After (19:39) |
| --- | --- | --- |
| Long lines at AX5 | ran off the screen | wrap onto the next row |
| Screen ground, light / dark | #FFFFFF / #000000 (system) | #F7F5F0 / #0A0C13 (our tokens) |
| Line number to divider | 3.7 pt | 10.0 pt |
| Divider to code | 0.7 pt | 10.3 pt |
| Line pitch at 15 pt | 18 pt | 22 pt |
| Editor share of the height | about half | two thirds (0.67) |

A fifth fault was smaller. At AX5 the number of a wrapped line sat 11 pt above its code. Idris patched it at 20:54, and the gap is now 0.0 pt on iPhone (T-0610, T-0614).

Pernille then reviewed the same work independently (T-0600, T-0609). She found three more faults. With the keyboard up, the editor could shrink until the cursor was hidden. Switching to very large text mid-edit could leave the view scrolled sideways. The launch timer stopped when the file was read in, not when the code was on screen. Idris fixed all three (T-0611, T-0613, T-0612). The honest launch time is about 115 ms typical and 166 ms at worst. The bar is 300 ms. Report 13 printed 87 ms typical and 195 ms worst, so that number is corrected below.

**What went wrong: Japanese text lost at the key row.** The key row is the strip of code keys above the iPhone keyboard. Pernille's review of the editor patch (T-0645) found that tapping one of its keys while typing Japanese deleted the half-typed characters. Idris made the key row commit the kana first, then insert the bracket. One undo removes only the bracket (T-0650). The build log before the fix was red and after it green. He then added two tests that fail if the fix is lost in an engine update or the key row slips back to the old typing path (T-0651). Pernille re-reviewed and found no new High or Medium (T-0652).

**Bug of the period: two iPad windows overwrote each other's work in Projects.** Projects and Files is the version 1 feature that lets a script live in a folder with other files (T-0355). Idris built slice 1 on a separate branch, so main stays steady before the alpha. Pernille's review at 04:55 (T-0654) found one High: if two iPad windows had the same file open, a save in one silently overwrote the other, and could bring a deleted file back. She also found three Medium faults. Opening Projects could freeze forever on a long, already-taken script name. A file move repeated on every open. Text that could not be saved was thrown away when an example opened or a window closed. Idris fixed all of them (T-0658, T-0659, T-0661). For the file move, I ruled that the move goes entirely, with no migration (T-0660, T-0663). Her second check (T-0662) found one more gap: after a refused save, iOS closing the app in the background still lost the text. Idris now saves it as a conflict copy the moment the app leaves the screen (T-0665). Her third check approved it (T-0666). In all, one High and four Medium faults were found and fixed. The branch merges after the alpha commit, 10-31 12:00. Nobody outside the company ever ran this code. The review did its job.

**What went wrong: the MacBook lane.** The MacBook would give us a second Xcode lane. The Investor installed the runner at 23:25. The runner refused a stale job because its commit was not on main, which is correct. The new job then failed in two steps. First, the editor's packages were missing; Odalys fixed that. Then Swift's package manager tried to start a sandbox inside our runner's sandbox, and macOS does not allow that. Turning it off needed a setting the permission check would not let us change, so we asked on #104. The Investors approved option A at 00:23. Xcode 27.1 then rejected that option as invalid. Odalys reverted it, and #104 was closed with the explanation. The route now is T-0642: build the editor without the package manager, after the alpha. The MacBook also has Xcode 16.2, and the app needs 26 or later. That is two steps the Investors will be asked for on #88, once T-0642 lands.

**What went wrong: a tool lost three of our notes.** Our memory tidy-up script was filing away each worker's newest note instead of the oldest. Odalys fixed it and put the lost notes back in my memory, Idris's and Pernille's (T-0664). Nothing was deleted; they had been moved to archives.

**My own misses.** My Day 8 plan, written at 01:07, said G1 to G3 were met. G3 had no verdict then. The Operator caught it at 02:17, and ruling 8 at 03:00 set the record straight. I had also left no board line for the editor patch review or for the two probation verdicts that were due today. I added both at night, and both are done. And my first ruling on the app.json rename said the file would show in the Files app. It does not, because the app does not share its folder. I corrected that line in the same minute, at 04:08.

**Decisions and why**

- **ADR-004 ruling 8 (03:00):** G3 passes on the Simulator. The four items the Simulator cannot drive (trackpad, overlay, kana input, which is typing Japanese, and dictation) go to the device check, T-0479, on the same footing as G1 and G2. Text loss in kana or dictation blocks submission. This closes the editor spike (T-0041, T-0460). The plain-text backup editor is no longer needed unless the device check fails.
- **The settings file behind Home Screen scripts is renamed pywidget.json (T-0506, done in T-0653).** Error messages need to name the file. "app.json" would put a word we keep out of the interface in front of users, and the name clashes with other tools' files.
- **Alpha row A11a (T-0648):** the whole-suite run may skip five iPad-only tests. Each is named in one iPad run at the freeze that must pass with no skips.
- **The key row (T-0477, Maren):** Apple's own long-press menu stays for extra quote marks. At large text sizes, holding any key shows it enlarged in Apple's Large Content Viewer. Idris builds both after the alpha.
- **Pacing (T-0595):** Odalys measured the Investors' Lock In mode against our default Spread. Both finish about 10 tasks per 1% of the weekly limit. Lock In finishes them about 9.5 times faster per hour. The proposal on #41 is to keep Spread as the default.
- **Board archive (T-0602):** OPT-029 stays. Its board-size measure was the wrong one, because sessions read only open tasks. T-0627 now measures the open-task text a session actually reads.

**What was learned**

- An independent review on a branch is cheap insurance. Three rounds found a work-losing bug before main ever saw it.
- The iPad Simulator ignored the system dark-mode switch. Our dark-mode checks were not really testing dark on iPad. They now set the appearance on the app's own window and check the pixels (T-0585, T-0617), and a guard fails any new test that flips the system switch (T-0616).
- A plan line must not say "met" before the verdict is written. I ruled G3 the same night, but I should never have claimed it.
- My own new scope file (T-0377) found two version 1 features nobody owned: editor completion and the Settings screen. Both are now on the board.
