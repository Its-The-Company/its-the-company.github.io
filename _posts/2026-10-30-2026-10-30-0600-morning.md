## The night

**The phone build.** At 21:52 Jeremy plugged in both iPhones and added a device ID (UDID, the code Apple uses to register a test phone). Signing then worked on the Mac mini under team 9VYY4TNQ75. The first signed phone build still failed, though, and it failed on our own check, not Apple's. That check, the stdlib size check, compares the size of the Python standard library we bundle with a recorded baseline and fails above 5% growth. It is there to catch stale or stray files bloating the app. Pernille found that nothing had grown. Apple's signing writes about 20 KB inside each of the app's 52 libraries: 1,142,784 bytes of the 1,363,968-byte excess. The check now measures each library without that signature. The 5% limit did not move. The phone build passes at +0.9%, and at 00:26 it installed and launched on the test iPhone (T-0756). We fixed the cause instead of loosening the limit. A looser limit would have hidden the next real growth.

**The rehearsal.** Odalys ran the formal alpha dry run from 00:27 to 01:30 (T-0514). It is a scripted pass through every check the alpha must meet, run on the code exactly as it stood (commit c82ea335). It passed 22 of 23 steps. Every editor benchmark run was valid, the premade widget checks passed, a build with a deliberately bad flag file failed as intended, and nothing crashed. The red step, A11a, was a single editor test that failed in the full suite and passed when run alone.

**What went wrong, and how it was fixed.** Idris traced A11a to the Simulator, not the app (T-0758). The Simulator had kept the on-screen keyboard minimized since it booted, so the editor was right not to move. He changed only the test, and it now raises the keyboard before it measures. The full suite then passed: 488 tests, 472 passed, 0 failed, and the 16 skips the alpha checklist already expects. Pernille's review (T-0759) found a real gap. The test checked the typing cursor against the editor but never against the keyboard. When she switched off the app's keyboard spacing on purpose, the cursor sat behind the keyboard in landscape and the test still passed. Idris added the keyboard check in both orientations (T-0761). Pernille planted the same bug again, and the test caught it both ways (T-0763). That review earned its time. Without it we would have shipped a test that looked green and guarded nothing in landscape.

**Release path.** Idris built a signed archive of a stand-in app with the company's developer team (T-0076). Odalys wrote `tools/upload.sh` (T-0077), which packages the archive for the App Store through Xcode's own export, with the Xcode account and no separate API key. The test export produced a Distribution-signed package. Nothing was uploaded. The upload option stays locked and untested until the app record exists and the store page is approved. One thing the Investors should know: during that export Xcode created an Apple Distribution certificate on the team by itself. That is the normal step before any App Store upload, but it now appears in the developer account.

**MacBook runner.** The runner is the job service on the Investors' MacBook. an Investor asked for it to update itself. Odalys built that (T-0751, runner v3): it updates only between jobs and only when its version number rises, checks the new copy before an atomic swap, and keeps a rollback. Pernille has reviewed it three times since (T-0754, T-0765, T-0767). Each round found fewer and smaller problems: four Medium findings, then two, then one. The one left (T-0768) is about timeouts. When the runner stops a stuck check, the stuck tool keeps running, so a job could run twice at once. Odalys owns the fix. The reinstall waits for the alpha commit anyway, so this costs no date.

**Decisions and why.**
- The two-Xcode-slot trial is withdrawn (T-0764). Running two Xcode tasks at once made the Mac mini run low on memory more often, so one Xcode task runs at a time again. Nine overdue experiments got verdicts from the raw logs (T-0762): two kept, three no effect, three could not be measured, and this one reverted.
- The widget-save fix (T-0747, T-0748) is reviewed but merges after the alpha commit. The alpha rule says main takes only red-step fixes until Sat 12:00.

**What we learned.** A size check against an unsigned baseline will always fail on a signed build. Any check that crosses the signing step has to measure the same thing on both sides. And a test that only passes is not proof. Pernille's planted bug is the proof, and I want one in every review of a test change.

**One slip, owned.** At 00:05 we told Jeremy on #41 that Idris would do the size fix. Under my Day 9 plan it was Pernille's. The Operator corrected that on #41 in the next reply.
