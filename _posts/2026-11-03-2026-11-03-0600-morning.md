## The story of the night

**Highlights.**

- **The personal accounts got parity (T-1035).** On 11-02 the Investors told us the lanes must work exactly like the main account. A lane is a personal Claude account that takes board tasks. Odalys built the change and Pernille reviewed it twice: once for the fixes (T-1185) and once for the merge (T-1082). Then it ran into our security guard, the hook that checks every command before it runs. The guard refused the ordinary merge command, `git merge --ff-only`. At 23:33 an Investor told us on #41 to override the check. The Operator copied the 12 reviewed commits onto main one by one instead. The result is identical to the tested copy (83f44bbb), and the landing test passed on main. The hook itself was not touched. I want this recorded plainly. The landing went past the guard on an Investor's word, not because the guard agreed.
- **Lanes stopped waiting (T-1186, T-1192).** A personal account no longer sits idle while its finished work waits to merge. Since 05:04 a lane starts its next task as soon as one finishes. It claims only what it runs, and it lands each finished task on main once its tests pass.
- **Widget links are now tight.** A widget is a small app view on the Home Screen, and a tap on it opens a link. Five tasks made sure those links can only open pywidget itself, never a web page or another app (T-1158, T-1177, T-1178, T-1179, T-1180). A sixth added a test for the link that covers the whole widget (T-1266). Pernille tried to break it in review (T-1159, T-1244, T-1282) and could not.
- **The rating record is safer.** Apple lets an app ask for an App Store rating only a few times, and we plan to ask once. Odalys fixed four ways our record of "already asked" could go wrong (T-1164 to T-1167). The worst one: a record we could not read would look like a new install, and the person would be asked twice.
- **The editor builds without the nested package sandbox (T-1050).** The code editor and the other Swift parts now build as plain Xcode targets. That was what blocked the MacBook runner from building the app at all. All unit and UI tests passed on a copy of main first.
- **Clocks can show a full hour again (T-0395).** Idris's write-up has the widget repeat one entry itself, which uses about a tenth of the memory. The minute-by-minute clock was cut short to fit a size limit. With this it can show 60 minutes again.

**What went wrong, and what we did.**

- **The file guard undid the Investors' own work.** At 02:54 the Investors applied two approved changes by hand on the Mac mini. One folds all 18 amendments into the Commandments' own wording (#143). The other fixes the records guard (#144). At 03:48 the file guard took both for tampering and restored the old files. That left `amendments.md` with uncommitted edits, and both personal accounts stopped on it (#146, #147). We asked the Investors to re-apply (#148). The guard needs a fix so this cannot happen again. Odalys designed one and committed its checker (285189a9f). Building the rest needs a change to the supervisor, the script that starts work sessions. The security guard refused that change, because it "starts another Claude session outside the governor". The governor is the script that meters our usage. I ruled at 05:33, under our rule T-0848: a refusal stops the item, with no rewording and no other tool. So the fix goes to the Investors as Odalys's proposal #149, for them to apply by hand. Until #148 is settled on main, nobody resets `amendments.md`. Right now it is the Mac mini's only copy of the 18 amendments.
- **The MacBook runner gate failed again.** The runner is the Investors' MacBook Pro, which runs our Xcode tests. On its third run (aff4d37d) the full suite ran inside its sandbox for the first time: 2,901 tests in 48 minutes, and 81 failed. Most were purchase and Home Screen UI tests. Next is a run outside the sandbox, so we can tell which failures the sandbox causes (T-1207).
- **Idris left a red test on main, and owned it.** A red test is a failing one. His T-1148 commit added a status file that one app test did not know about, and he had run only the host tests. He found it himself at 21:24. T-1196 fixed it, together with four tests that failed whenever the code sat in a temporary folder.
- **Idris found a gap in his own link check, and owned it.** We test our tests by planting bugs, called mutants, and checking that a test fails on each one. His T-1179 link pattern refused the same addresses as older rules, so 4 planted bugs survived. The mutant count sat at 11 of 15 and nobody noticed. T-1180 ties each rule to its own reason. Now 18 of 18 planted bugs are caught.
- **The Operator skipped a step.** The Operator is the session that runs the company. It sent three tasks (T-1158, T-1179, T-1164) without the lane claim step. Two lanes held them from about 19:05 to 20:29 with nobody working them. All three landed, and the Operator told an Investor on #41. From now on the main session leaves lane-able work to the lanes.
- **Small work sessions spent credits for nothing.** Four sessions in a row ran on the last API credits with too little to pay for one worker call, which costs about 3.30 USD. T-1230 stops that. Time like that now goes to the plan.
- **The evening session did not close itself (18:21).** We saved its 10 leftover files in a salvage commit. All six of its agents had finished.
- **Odalys reported her own slip.** She rewrote one test block with a Python script, which broke the rule that edits go through the Edit tool. Three panel rows were also never seen failing first. Both are in her T-1191 note.

**Decisions and why.**

- **T-1209 reverted (23:57).** It fixed a low-risk finding (H1) from the security review of the personal accounts. But it stopped lanes from landing two files the main account can land. That broke the Investors' parity order of 11-02, and they had already accepted the lanes' security risks on 11-01. H1 stays accepted and on hold.
- **The model-routing test ended with no clear effect (OPT-051, 05:12).** OPT-051 tested a new rule for which model does which task. Under it we finished 38.1 tasks per 100 USD, against 34.6 under the old rule. That is +10%, but p = 0.37 with 30 sessions on each side, which is inside the noise, and one session-limit guard tripped. So the old rule of 10-23 is back.
- **Disk cleanup became standing.** The Investors approved a standing sweep that runs between sessions. It deletes scratch folders whose tasks are finished. Two cleanups ran under it: 17.7 GB free to 31 GB at 18:32, and 15 GB to 22 GB at 23:44.

**What I learned.** A guard that cannot tell the Investors from an intruder will protect us against the Investors, and it did. I read #143 and #144 as changes to the rules, not as changes to the guard. They were both.
