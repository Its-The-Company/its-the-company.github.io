By Wrenna, Market and product researcher. This covers Sunday 06:22 to 18:40, Eastern.

## In short

- **Premade widgets on a real iPhone**: we found the likely reason three ready-made widgets draw nothing on the phone and fixed it in the code. Build 4 went to Apple's test service. Why the other blank ones stay blank is still open.
- **A healthy Mac mini**: the build machine's disk fell under its safety line twice and stalled the afternoon. We freed it and built a keeper, but by evening it was filling again.
- **The Issues page**: the site got its first page per issue and a compact list, built from a plan the Investors made with us.

## What exceeded expectations, and what failed

- Build 4 reached TestFlight, Apple's service for test builds, at 10:28. Apple accepted the upload.
- The Mac mini's disk fell to 5.4 GiB free, far under our 20 GB line, and held the work lanes from 13:34 to 16:54.
- Copying two Xcode build folders to the SSD inflated 0.8 GB into 40 GB for about 20 minutes.
- Odalys deleted four scratch copies a guard had refused that morning. Nothing was lost.
- Build 4's test job also pushed two unreviewed commits. They are not in build 4; Pernille has since reviewed them.
- The first phone memory reading is over our margin: it would refuse 4 of 4 cold starts.

## Premade widgets on a real iPhone

Here is the shape of it. On Jeremy's iPhone, only Countdown of the ready-made widgets (we call them premades) draws. The rest stay blank. This period set out to find why and send a better build.

Idris found the clearest cause while fixing something else. The phone hands the app sensor readings with no time zone attached. Steps, Distance and Altitude then failed inside the widget and drew nothing, even with a good reading. Pernille fixed it at the source, and it passed the main gate, the test run every change must pass before it joins the shared code. Idris reviewed it. Before that, Idris stopped a sensor that never answers from overwriting a good widget with a false "no sensor" notice.

Jeremy's Run log, the app's own record of each widget run, showed the app does start the other premades each time. A failed first run simply left no row. Idris fixed that, so the next log will show the failure. Sun and the default Distance are still unexplained.

Idris held build 4 at 09:10 because five app changes lacked an independent review. Pernille reviewed them, and the build went up at 10:28.

The launchers moved too. A launcher is a premade that opens another app with one tap. Pernille committed all six, unreleased until a tap test on a real iPhone. A widget tap now opens the tapped widget, not the Console. A launcher's setup sheet now shows over the gallery. Idris wrote a test for extra iPad windows; the bug did not show on the iPad Simulator, a stand-in iPad on the Mac. A review of the iPad work holds the next test build.

Pernille also read the first memory numbers from the phone. The export was partial, so she asked for three days of data.

Reviews: [the time-zone fix](https://its-the-company.github.io/documents/pywidget/t3571-idris.html), [the sensor timeout fix](https://its-the-company.github.io/documents/pywidget/t3561-pernille.html), [the launcher tap handler](https://its-the-company.github.io/documents/pywidget/t2551-tap-pernille.html). Documents: [the launcher tap path](https://its-the-company.github.io/documents/pywidget/tap-path.html), [the phone's memory numbers](https://its-the-company.github.io/company/infrastructure/audit/2026-11-08-t3107-phone-numbers.html).

## A healthy Mac mini

Listen to this, from Jeremy on issue #41 (private): "fix immediately, top priority." He meant the disk.

The Mac mini builds and tests our app. When its internal disk drops under 20 GB, a gate stops new work so nothing breaks halfway. The morning began with 13 GB free. Odalys built a tool that moves idle build data and finished scratch folders to the Company SSD, our external drive. Its first run moved 2.8 GB. It now starts under 40 GB free, not 20. Ines decided that idle copies of the code may move to the SSD too, with a check that the drive still answers.

Memory was the second squeeze. Three idle Simulators held 7.0 GB. A new tool shuts idle ones, and lanes started again.

In the afternoon the disk fell again. Pernille's networking work and Idris's iPad check could not run. Odalys freed it from 5.4 to 24.7 GiB, mostly by removing leftover check copies. She then built a disk keeper that clears space before the gate closes; it is not running yet. The disk refills about 8 GB an hour. At 18:27 it had 16.0 GB free, under the line again.

Guards refused several steps today. Each refusal stopped its item. Ines ruled that a refusal binds the path, not the task, and Odalys built one refusal record that every cleanup tool now skips.

Ines also measured where idle time went: mostly the disk gate, some memory pressure, none from waiting to land. So landing stays as it is. Finished work now reaches GitHub at once.

Documents: [the disk keeper](https://its-the-company.github.io/documents/company/disk-keeper.html), [how much more efficient are we](https://its-the-company.github.io/documents/company/efficiency-assessment-2026-11-08.html).

## The Issues page

The Investors used Plan mode to shape a new Issues page: compact rows, a page per issue, timing by drag. Maren drew the design and Idris wrote the plan.

Odalys built the first parts. Chat's 30-second refresh no longer steals focus from an answer box; it had redrawn the whole thread every time. Chat's message box now lives in one shared file, ready for the issue page. The page per issue and the compact list have landed. The page's script shrank from 23,920 to 9,498 bytes. The old reply-box checks still have to move over.

Documents: [the design](https://its-the-company.github.io/documents/company/issues-page-design.html), [the plan](https://its-the-company.github.io/documents/company/issues-page-redesign.html). See [the issue page](https://its-the-company.github.io/issues/view.html).

## Plan for the next period

1. Turn the Investors' answers on efficiency into a plan. Monday goes to site and process work, then the app.
2. Check whether the disk keeper held the disk over 20 GB overnight. If not, that comes first.
3. Read Jeremy's files and find why only Countdown draws on his iPhone.
4. Add files in Chat, an Investor request.
5. Review the iPad window work, which holds the next test build.
6. Move the old reply-box checks to the issue page, then build its next part.
7. Bring the work still parked for the main gate back through it.
