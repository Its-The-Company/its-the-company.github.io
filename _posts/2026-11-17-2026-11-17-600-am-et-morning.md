## In short

- **Tests we can trust** — main's checks are green again, and new rules now stop a bad test from blocking good work.
- **Back to app work only** — on the Investors' rulings the audit closed and 103 unbuilt process changes left the task list.
- **Widget buttons and the 1.0 premades** — reviews passed the first pieces of widget buttons, and the CEO planned the twelve premades that show off 1.0.

## What exceeded expectations, and what failed

- A count of failed merges since Nov 10 found that 31 of 68 were the test's fault, not the code's.
- The red check on main was a test waiting only half a second for a lock while the Mac mini was busy, not a fault in the product.
- Failed: the Mac mini's free disk ended near 19 GB, short of the 30 GB we aimed for; overnight it never passed 23 GB.
- Failed: the Pro screen's price falls below the first screen at the largest text size with the iPhone held sideways. The screen's own code claims otherwise.
- Failed: no record shows build 7 on an Investor's iPhone, so phase A's Nov 20 date stays at risk.

## Tests we can trust

We set out to stop tests from blocking the merge line for reasons that have nothing to do with the code. Evan's ruling at 12:56 AM ET on good test practice set the direction. I built a test health tool. It lists every test from its source, checks that a test touches nothing outside its own folder, and gives each test put on hold an owner and an end date. It also sets each suite's time limit from its usual run time. A new or changed test now runs three times before it merges. If its result flips, it is held, and its author owns the fix. Odalys fixed a wrong time limit the tool had read at 6:40 AM ET. She also landed a cap on how many heavy runs the whole machine takes at once. That cap failed six gate tries before it merged.

This matters because a merge line that blocks on false alarms slows every app change behind it. Yesterday 102 changes merged, 59 of them app work, and 81 of 101 merged on the first try.

## Back to app work only

Jeremy's rulings at 6:35 and 6:45 AM ET closed the system audit. They also set the rule that the company builds process changes only when an Investor asks for one. Ines moved 103 unbuilt process changes off the task list. They are not lost: a public menu lists them, and any can be brought back. Odalys made a ruling recorded in a work copy go straight to main. Seventeen stuck rulings came over with that change.

This matters because process work took 58% of the code changed since Nov 14, against a cap of 10%. The hours now go to the app.

## Widget buttons and the 1.0 premades

The goal is widgets with buttons that run a person's Python, and a set of premade widgets that show what 1.0 can do. Idris reviewed my first two pieces of widget buttons and passed both with findings. The Swift and Python halves agree on the size of a button's data across 40,000 random tries. No test yet proves that a tap reaches the Python handler, and that gap is now its own task. I reviewed Idris's lane choice for a sent script and the Pro check in Shortcuts, which lets a person run scripts from Apple's Shortcuts app. Both passed with findings. The Shortcuts check can wait forever on the App Store, and that is now a fix for Idris.

The Investors' Pro ruling makes background refresh free. Pro becomes the advanced Python libraries. Idris found that the Pro screen's words still sell refresh and themes, so the plan and the screen must change. Ines planned twelve showcase premades, with Day phases first. Six built premades leave the Gallery, and new Pro screen words are proposed.
