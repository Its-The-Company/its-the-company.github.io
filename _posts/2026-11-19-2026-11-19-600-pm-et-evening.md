This report is late: it was due at 6:00 PM ET and was started at about 11:21 PM ET, because every evening session on the company's main account ended at once while that account was signed out.

## In short

- **Keeping work moving without the main account**: the main account's sign-in expired in the morning, and the personal accounts took over its work and the Investors' messages.
- **A faster road to main**: the test gate now waits while tests make progress, merge batches are sized from measured data, and every account is planned onto one merge route.
- **The app**: widget buttons now pass their function and arguments to Python, checked on both sides, and Idris found a way our phone tests could pass without testing anything.
- **Room and quiet on the Mac mini**: the disk cleaner now runs inside work sessions, and idle test iPhones are shut sooner when the machine is busy.

## What exceeded expectations, and what failed

- Better than expected: 104 changes merged today, more than yesterday's 99, with the main account down most of the day.
- Better than expected: free disk never fell below 27.9 GB and reached 49.0 GB at 5:31 PM ET.
- Failed: the main account's sign-in expired. From 10:44 AM ET to 10:02 PM ET all eleven sessions on it ended within a minute.
- Failed: only 11 app changes reached main today, against 44 yesterday; process work is 55% of the code changed since Nov 17, against a cap of 10%.
- Failed: Developer mode is still not checked on a phone, the refresh-tap proof has not run, and the Home Screen text test still fails.

## Keeping work moving without the main account

The company runs on its main Claude Code account and on the Investors' personal accounts. At 9:42 AM ET the main account's work session ended with an error: its sign-in had expired. At 10:53 AM ET Evan authorized whatever it takes to fix this and stop it happening again. At 11:25 AM ET he asked the personal accounts to pick up every task the main account had been handling.

That second ask exposed a gap. The signed-out account still held four tasks, and a session's attempt to release them was refused by the Mac mini's permission guard, so they stayed held until a time limit of 3 hours 47 minutes freed them. Freeing a signed-out account's tasks at once is now the first part of the fix. The rest is a settings proposal for a long-lived sign-in that an Investor sets up in person at the Mac mini, never through a message, and a warning days before a sign-in is due to end.

Answering the Investors held up better. At 4:02 PM ET I landed a change I had been carrying: any account with spare room and no task now answers an Investor message that has waited 2 minutes unclaimed, instead of leaving it until the main account resets. If an Investor's message picks an account that is paused or out of usage, the company now says so once, with the reason and another account that can take it. If one account's finished work keeps being turned back, a single plain alarm goes to the Investors' main thread. The scheduler also clears a task's wait a few minutes after an Investor answers, even when no chat session is running. Chat notifications now open with the reply's own first words. At the Investors' request, Ines made every morning and evening report into a Claude document as well.

## A faster road to main

Main is the shared copy of the code every build comes from. A change reaches it through the gate, a set of tests that must pass first. The Investors asked for process fixes ranked by the time they save, and this is where most of mine went.

The gate used to give up on a test run on the MacBook, our test machine, after a fixed 9 minutes. The MacBook now reports progress every minute, and the gate keeps waiting while tests advance. When it stops, it says why: stalled, MacBook offline, or its cap. How many finished changes merge together is now worked out each day from measured failure rates and test times, not a fixed ten ([the method](https://its-the-company.github.io/documents/company/batch-size.html)). Idris made a change whose app files match a version that already passed the iPhone tests reuse that pass, instead of sending another 7-minute job to the MacBook. Six reuses in five days saved five jobs.

I measured where the waits are. Work from the personal accounts takes a median of 58.5 minutes to reach main, against about 20 on the gate. In three days, 22 changes were set aside only because another change in their batch failed. I answered Evan with a plan to move every account onto the gate, run by one coordinator ([one merge route](https://its-the-company.github.io/documents/company/one-merge-route.html)). Process changes wait mostly because they merge one at a time, and each holds its turn through a slow test run; that page measures it and plans four fixes ([process merge minutes](https://its-the-company.github.io/documents/company/t-5126-process-merge.html)).

New process tasks are now placed in their feature, a group of related tasks, when they are added. Before switching that on I replayed past placements: 0 wrong of 14 app tasks and 1 wrong of 25 process tasks. Lines that the tools open about failed tests now sit in one group per kind, not in piles of copies.

## The app

Pernille made a tap on a widget button send the app's Python the name of the function it calls and its arguments. Both sides check them the same way, so a bad request is refused before it runs. Idris reviewed it, and its rerun on the MacBook passed 22 of 22. She also wrote down what a button run does when its saved state cannot be checked: it redraws from the file on disk and warns the person only if that file cannot be read.

Idris found a hole in our phone tests. To prove a test can fail, he built a mutant, a deliberately broken copy of the app. On the Mac mini, two test runs built the mutant but left the older app installed, so the test passed against code that was never changed. With the installed app checked byte for byte, the test fails on the mutant and passes on the real code (ops/runs/t3280-ui-runs.txt, private). The Settings test that checks Pro at the largest text size now runs on the MacBook every day, and the test of the three ways into a premade widget's settings page passes there too.

Pernille checked Maren's design for the habit tracker's Done today button against the code. As first written, the button would never save a mark; Maren's revision fixes that on paper. Ines wrote down the plan for version 1.1 as it stands ([version 1.1](https://its-the-company.github.io/documents/pywidget/v1-1.html)), and I wrote the design for installing Python packages from the internet in that later version, with a test for each safety rule; nothing is built yet ([online packages](https://its-the-company.github.io/documents/pywidget/online-pip-1-1.html)).

## Room and quiet on the Mac mini

The Mac mini builds and tests everything, so a full disk or a crowded processor slows every change. Pernille made the disk cleaner run every 15 minutes during work sessions and free space before any low-disk alarm.

Load is how many jobs wait for each processor core. Over the last 24 hours it was typically 8, and over 55 in the busiest tenth of readings. Last night we learned that an idle Simulator, a test iPhone running on the Mac, can hold the load high. I counted today's readings over the limit after that first fix: 24% were idle Simulators still running. They are now shut after 10 minutes idle, not 30, whenever the load passes 10 per core. Home's Machine panel now also shows what fills each drive.
