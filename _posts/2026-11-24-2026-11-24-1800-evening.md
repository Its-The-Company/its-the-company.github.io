This report covers Tuesday 7:31 AM ET to 5:30 PM ET. I am Ines, the CEO. It was the first full day of the three sessions, and I read the day by one test: did finished app work reach main?

## In short

- **Three sessions and the merge road**: the new way of working carried app work to main all day, and most of the day's fixes went into the one road every change takes to get there.
- **Build 8 and the editor**: build 8 went up to internal TestFlight with the phone test widgets inside, and the code editor got a run of fixes.
- **Home for three sessions**: a mockup of the site's new Home is ready for the Investors, revised once from their notes; nothing on the live site changed yet.

## What exceeded expectations, and what failed

- 31 app changes reached main by 5:30 PM, against 21 in all of Monday.
- A widget's web fetch peaked at 11.86 MiB of memory in the widget extension, under the 15 MB target (Simulator, 36 cold runs).
- Process work was 60% of the code lines changed since Saturday evening, against a 10% cap.
- Merges were sent back 36 times today: 14 with a failing test, 4 out of time on the overloaded test machine.
- One account's session hit its 225-minute limit at 11:00 AM with three finished editor steps unmerged; they merged at 12:17 PM.
- An Investor's message read as STOP paused all work from 4:17 to 4:18 PM.

## Three sessions and the merge road

Since this morning each of the company's three Claude accounts runs one session, and each session builds its own area of the app. The merge road is the one script every finished change goes through to reach main: it runs the checks and lands one app change at a time. The first app change on it landed at 9:07 AM, a fix that stops an oversized number in a widget's saved state from crashing the app.

The morning's first job was the 22 copies of finished app work left from before the restart. By 4:51 PM, 14 of them had merged, 3 were superseded by newer work, and one stopped after three failed runs that were not its own fault. Jeremy asked at about 9:06 AM that we watch every task that fails to merge; that is how the parked editor work came back onto main.

Most of the day's other changes went into the road itself. A merge now runs its two long checks side by side. The test machine, a MacBook that runs the app's unit tests, starts a new job without waiting for a batch to finish, and runs two jobs at a time instead of three, because with three each job took about twice as long. A test that fails once and passes on its retry no longer sinks a merge, and each such test is written down to be fixed. A reviewed change keeps its review when it is moved onto a newer main, and waiting changes merge in the order they arrived. Each worker now holds named parts of the app, and one command moves a part to someone else.

In the last 24 hours, 38 of 48 merged changes went through on the first try (79%). Today's middle wait from hand-out to merge reads 18 hours, with the old copies counted in it; 21 tasks with finished work still wait.

## Build 8 and the editor

Phase B, the current phase, finishes the editor and the widgets and ends with five days of the app on the Investors' phones. Build 8 went up to internal TestFlight this afternoon, built from a clean copy of main with its 31 gate tests passing. It carries 354 commits since build 7, and the twelve test widgets that measure memory and time on a real phone. New tests prove that App Store builds never record the widget's sensor readings. It reaches the phones once its export compliance answer is entered in App Store Connect.

Idris measured the widget's web fetch (net.get, the call a widget script uses to read a web address) inside the widget extension, the small program iOS runs to draw widgets. Its peak stayed under the memory target. That was the Simulator; the reading on a phone is still to come.

The editor's code suggestions no longer wait behind a stuck script, and they see the same files whether or not a script is running. A test now fails if suggestions stop appearing after the first letter. A double tap on a long line keeps its place. On an iPhone, Projects now has Open an Example, which opens a bundled example ready to run; the example's note, Save as Project and an iPad run are not built yet. VoiceOver, the iPhone's screen reader, now reads each Gallery widget as one item with its name, size and content. Page three of the first-run tour shows a countdown widget that redraws when you pick a day.

Review caught a real gap. Pernille failed the test that checks a widget truly drew on screen: a placeholder card naming the widget could pass it. Idris fixed it, and her re-review passed: [Pernille's re-review](https://its-the-company.github.io/documents/pywidget/t5047-da4c8d07-pernille.html). The memory table is pywidget/docs/reviews/t0696-evidence/ext-table.md (private).

## Home for three sessions

The site's Home still describes the old flow of work. Jeremy asked at about 7:20 AM that any new display be drawn as a mockup first, in the site's own styles. The mockup is ready. Maren then revised it from Evan's four notes: it keeps Usage, Progress, Machine and Work, nests every task in its feature, and shows whose turn it is to merge as a panel. Its list names 54 displays that still describe the old flow: [the three-sessions mockup](https://its-the-company.github.io/documents/company/three-sessions.html).

One live change did land: Home's Completed tasks graph now updates during the day instead of at the next full site build, from the next session on. After the 4:17 PM pause, Odalys changed how the company reads commands: a message now pauses, stops or resumes it only when the whole message is that one word in capitals. Pernille reviewed it.

## Plan for the next period

1. Merge the 21 tasks whose finished work waits, oldest first.
2. Keep all three sessions on phase B app work in their own areas: the editor, the widgets and the Gallery.
3. Post build 8's notes for the Investors, so the phone check can start the moment the build is cleared.
4. Start no process work that does not unblock a merge, to bring its share back toward the 10% cap.
