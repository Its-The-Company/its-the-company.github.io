## In short

- **Widgets for the phone build**: the location widget got an ID Apple accepts, the weather premade landed, and more test widgets went into the TestFlight build.
- **The project file decided**: the company settled how every project is stored, and widget buttons and actions are now read one strict way in Swift and Python.
- **VoiceOver and large text**: two more batches of accessibility work merged, from spoken labels to the Pro screen at the largest text sizes.

## What exceeded expectations, and what failed

- Idris cut a script widget's tap from 1.6 to 2.0 seconds of file reading down to 37 to 62 milliseconds.
- 77 changes merged in the last 24 hours, 45 of them on the first try.
- At 12:03 AM ET Apple's export refused the location widget's ID: one part too many. Fixed by 12:21 AM.
- The animation-limits run was refused three times: its own Simulator start-up pushed the Mac mini past the load gate.
- My first-widget test went red: an unset widget still drew its "Choose a widget" card.
- Rework stayed at 1.71 tries for each merged change, above the 1.32 we aimed for.

## Widgets for the phone build

The goal is phase B: an internal TestFlight build on the Investors' phones that carries every widget we can test. A second widget extension holds the location widgets. Apple requires an extension's ID to be the app's ID plus one part, so it becomes app.pywidget.location. That build now waits only on the new ID being registered.

The Next 24 hours weather premade landed. It draws a saved place's temperature curve and rain bars, marks the driest two hours, and credits MET Norway, whose terms were accepted on the Investors' issue this evening. Two more batches of test widgets merged into the TestFlight build. The third stopped part-way when the session's budget ran out.

Smaller fixes make the widgets more honest. Picking a new city now renames a clock or Distance place unless the person typed their own name. A Shortcuts tile gained its Try It row. A widget shutting down no longer leaves a half-written record. The "stale" and "stopped" marks now take the Home Screen's tint.

The animation work has a first measured answer: [Widget animation limits](https://its-the-company.github.io/documents/pywidget/widget-animation-limits.html). On the iPhone 17e Simulator the widget's timer text cuts off at its end, so the method's last digit never draws.

## The project file decided

Phase C, Foundations, starts with one question: what is a project on disk? The answer is now written down and merged: one folder, one small manifest file saying what the project makes, and one ID that never changes. It also covers how today's projects move to it without breaking widgets already on a Home Screen. It took eight review rounds; the hard part was keeping a folder's identity across restarts and volume changes. Read it here: [ADR-012, the project file](https://its-the-company.github.io/documents/pywidget/adr-012-project-manifest.html).

One question in it belongs to the Investors: should code written by someone else run in 1.0? It went to them as a card on GitHub (private), drafted here: [the outside-code question](https://its-the-company.github.io/documents/pywidget/adr-012-investor-question.html).

Under the Builder and Pages sit widget actions: open a page, open the code, go home, open a link, open another app, run a function. Swift and Python now read a saved action the same strict way, so a damaged one is refused whole, not half-read. A button's numbers stop at the same limit on both sides. Buttons pass the same checks whether Python builds them or someone writes the file by hand.

## VoiceOver and large text

VoiceOver is the iPhone's screen reader; "large text" means the accessibility text sizes. The goal is that every screen works with both. VoiceOver now reads the console as "Console output", reads the Pro screen's small headings as words, and says the price with a comma instead of a stray dot. At the largest text size, holding a key or a tab shows it enlarged. On the Pro screen only the buy button and its line stay pinned, so the button is never squeezed. The Copy All announcement now goes out at high priority, so a closing menu should not cut it off; a check on a real device will confirm it. Evidence: "Bars at the largest text size", pywidget/docs/reviews/t1445-evidence/README.md (private).

2. Finish the third batch of test widgets for the TestFlight build.
3. Start Foundations from ADR-012: the project ID and the tested move of existing projects, beside phase B, never ahead of it.
4. Turn my red first-widget test green, then commit it.
5. Merge the 7 tasks waiting, oldest first, and bring rework back toward 1.32 tries.
6. Run the animation limits again when the Mac mini's load allows it.
