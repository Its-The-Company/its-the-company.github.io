## Verdict

**PASS with findings: three medium, six low.** The path rules hold where the board line pointed: an absolute
entry, `..`, a symlink out (relative, absolute, through a folder), app.json as a symlink, a directory or a FIFO,
and the size cap all refuse with the right code. The run sets cwd, `sys.path[0]`, `argv[0]` and `__file__` as
s7 says, and a refused manifest ends as `error` with empty `frames` before any user code. No message calls a
project an "app" (item 5). The fixture format can be read from XCTest as it stands. The three mediums are a
silent overwrite of someone else's app.json, a hostile string that escapes as `internal_error`, and a
containment case missing from the fixtures the Swift half depends on.

## Findings

**F1, medium: `write()` takes over an app.json that is not ours.** app_manifest.py:297-308. When the existing
file is a JSON object with no `schema` key, `write()` treats it as an unfinished manifest: it keeps the other keys
as `extra` and replaces `name`, `version`, `id` and `entry`. Scenario: a user imports a Flask project from
GitHub that carries Heroku's app.json (`{"name": "My Flask site", "description": ..., "env": ...}`), taps Make
App, and the file's `name` is silently replaced. Heroku's tooling now reads a file with pywidget's keys in it.
I ran it: "My Flask site" is gone. `read()` refuses the same file as `wrong_schema`, so the two disagree on
what is ours. Delta item 4 makes Python `write()` the reference for Swift's Make App, so the rule spreads. No
test covers it: my mutant that refuses a schema-less object survived. Fix: refuse any existing object whose
`schema` is not `pywidget.app`, missing included, with `wrong_schema` (the caller asks the user). Add the
schema-less case to `test_never_overwrites_newer_or_unreadable` and the mutant to app_manifest_mutants.json.

**F2, medium: lone surrogates get past the checks.** app_manifest.py:178-194 (parse), 113-133 (check_name,
check_entry), 243-257 (resolve_entry). JSON can carry `\ud800` as an escape, and `json.loads` turns it into a str
that is not Unicode scalars. (a) An entry of `"\ud800.py"` passes `check_entry`, then `os.path.realpath` raises
`UnicodeEncodeError`. That is not an `OSError` and not a ManifestError, so a project run ends as `internal_error`.
s7 says a refused manifest ends as `error` / `ManifestError`. (b) A name of `"x\ud800"` passes `read()`. Swift's
JSONSerialization refuses the same bytes (probe: "not in the correct format"), so Python says ok and Swift
says `not_json` for one file. (c)
An unknown key holding `"\udc00"` makes `write()` raise `UnicodeEncodeError` from `encode()`. Fix: in `parse()`,
refuse a document with any lone surrogate in any string or key as `not_json`. The simplest test of that is
`json.dumps(doc, ensure_ascii=False).encode("utf-8")` inside the existing try. Add three `text` fixture cases
(name, entry, unknown key) so Swift replays them.

**F3, medium: no fixture checks the sibling-prefix escape.** app_manifest.py:204-205 (`_under`),
cases.expect.json. A mutant that changes `_under` to `path.startswith(root)` (no separator) survives the whole
suite. The code is right today (probe: `entry_outside`). But the shared fixtures are the Swift half's only proof
of its containment check (delta item 3), and `hasPrefix(root)` is the usual Swift mistake. With it, an entry
symlink to `../project2/x.py` from `T/project` would pass on device. Fix: add the cases `entry-symlink-sibling-prefix`
(`x.py -> ../project2/x.py`, outside `project2/x.py`) and the same with an `@outside/project2/x.py` absolute
target, both `entry_outside`, plus the `_under` mutant. While in that file, see F4.

**F4, low: the field-rule boundary strings are in Python only.** test_app_manifest.py:170-181. NAMES, ENTRIES
and IDS hold the subtle cases (U+3000, U+1680 and U+00A0 as all-space names, `..py`, `a.Py`, 1021/1022-scalar
entries, 64/65 emoji, the nil-but-one UUID). Swift cannot replay them. Fix: move them into a `field_strings` block
in cases.expect.json with the expected verdict, read by both suites.

**F5, low: the version outcome depends on the interpreter.** app_manifest.py:136-145. A 5,000-digit version is
`newer_version` on 3.9.6 and `not_json` on 3.13.18 (int string limit). `1e400` parses to inf and is
`bad_version`, though it is greater than 1. Neither is a likely file. Fix: a `parse_int` hook that refuses more
than, say, 15 digits as `bad_version`, and `bad_version` for any non-finite float. Add one fixture.

**F6, low: `project` is not checked as an absolute path.** runner.py:733-739, app_manifest.py:197-201.
`os.path.realpath("")` is the process's cwd, and a relative path resolves against it. s7 says
`project: "<absolute folder>"`, and Swift should never send anything else. Fix: in `_prepare`, require a
non-empty absolute str and raise ValueError otherwise (`internal_error`, as for the other request faults).

**F7, low: `not_found` also covers a deleted project folder.** app_manifest.py:197-201, 42. When the folder is
gone (deleted after the Shortcuts picker listed it), the run screen says "This project has no app.json file",
which is not what happened. Fix: a `project_missing` code ("This project isn't in PyWidget any more."), or a
message that covers both.

**F8, low: stale fixture path in the module docstring.** app_manifest.py:10 names
`tests/bridge/fixtures/app_manifest.expect.json`. The file is `fixtures/app_manifest/cases.expect.json`.

**F9, low: defensive lines no test reaches.** The `fstat` recheck (227-228), the capped read loop (229-235)
and the temp-file unlink on a failed write (326-331) all survive a mutant. The FIFO case the board line names
is not tested anywhere, though it works (probe). The window between `resolve_entry` and the runner's
`open(path)` is a check-then-use race on the user's own files. I accept it. Fix: one Python test that makes a
FIFO app.json (`os.mkfifo`) for read and write. Optionally a fixture spec `{"fifo": true}`, which Swift can
build with `mkfifo(2)`.

## For T-0449 (my own read, not findings against this commit)

- The error object carries `type` and `message`, not the code. `text` starts with
  `_pywidget_runtime.app_manifest.ManifestError:`. The run screen shows `message`, never `text`. If Maren's
  copy is to replace Python's text on the run screen, the error needs the code. That would be a contract
  change, so it gets raised with Pernille, not assumed.
- Swift's JSONSerialization does not report duplicate keys, accepts UTF-16 and UTF-32, and reads a JSON `true`
  as an NSNumber that `as? Int` turns into 1. The Swift reader checks UTF-8 first and the bool type explicitly,
  and needs its own scan for a key named twice. The fixtures catch all three.
- Lengths count `unicodeScalars`, not `String.count`. The containment check uses `realpath(3)` on both sides,
  not `URL.resolvingSymlinksInPath()`, which drops `/private` and would break the prefix test in /var/folders.
- The fixture file goes into the test bundle as a resource. Symlinks are made after files, and `@outside/` is
  the temporary folder's path as given, unresolved, exactly as the Python builder does it.
