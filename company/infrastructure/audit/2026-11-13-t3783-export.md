## Why

Not location or motion. Each of the four catches a refused sensor inside read() and draws "Location is off" or
"Motion is off", ending `ok` (now held by `pywidget/tests/widgets/test_premade_refused.py`, 12 runs: not asked,
off, restricted). And Sun has no settings on the phone (nothing in the app writes `use_current`), so it calls no
sensor at all, yet it failed the same way in 16 ms.

The one call all four make before read() is `files.shared`, the premade's own settings folder
(`_premade.Store.open`). In the app it is `SystemFiles.scriptFolder` (FilesCall.swift), which checked that the folder's
parent is the scripts root by comparing `standardizedFileURL` paths. `standardizedFileURL` drops a leading `/private`
only from a path that exists. On an iPhone the App Group is under `[local folder]` (`/var` is a link to
`/private/var`): the existing root came out as `/var/.../scripts`, the folder not made yet as
`[local folder]`, the two differed, and the call answered PermissionDenied ("The
shared folder ... is outside PyWidget's scripts folder."). The folder is made only after that check, so it was never
made, and every run failed the same way. The Simulator's App Group has no `/private`, which is why no test and no
Simulator run saw it. Countdown, Quote and Habits run in the widget extension (`lane.json`), whose `files.shared`
(LaneDevice, WidgetFolder.url) standardizes the root first, so they were not hit.

Asked or not: the app asks for location and motion only from a Gallery tile's Allow (GalleryAsk, the Info.plist
purpose strings are there). Widget runs never prompt, by design. On the phone the premades never got far enough
to ask the sensor, so the export cannot say whether they were allowed.

## Checks

- Red, then green, on the Simulator, one class, local (XC_LOCAL=1): `DeviceModulesSlice2Tests.
  testSharedMakesAPremadeFolderUnderAPrivatePrefixedAppGroup` failed before the fix with exactly the phone's reply
  (`ops/runs/xcodebuild-20261113-104620.log`), and passed after it with the class 14/0
  (`ops/runs/xcodebuild-20261113-105042.log`). It builds the App Group under `/private/tmp` and first asserts that
  path has the phone's shape (the root loses `/private`, the folder not made yet keeps it).
- Host: `test_premade_refused.py` 3/0: refused sensors draw words and end `ok`; a refused folder gives the export's
  signature for all four (`error`, PermissionDenied, no tree, no sensor asked).
- Mac probe of the same Foundation call: `/private/tmp/.../scripts` standardizes to `/tmp/...`, a folder under it
  not made yet keeps `/private`.

## Fix

`SystemFiles.scriptFolder` makes the folder from the standardized root, as `WidgetFolder.url` already does. The link
and `..` refusals stay (same test).

## Addendum, 11-13 after the land (754904a541): the manifest and Countdown's rows

Two more files came at 10:54 AM ET (an Investor c6858012498): `20261113T155414-manifest.json` and
`20261113T155418-runs-pywidget.premade.countdown.jsonl`.

- Phone: iPhone15,4, "Version 26.6.2 (Build 23G90)", app 0.1 build 4, lane_flag true, record_only true. So iOS 26.6.2,
  not 27.2 as the board line said. Nothing in this path is gated on iOS 27: the deployment target is iOS 18.0 and
  App/Device, App/Gallery, App/Bridge, Shared/Bridge, ExtensionLane and Premades carry no `#available` or
  `@available(iOS ...)`. The `/private` App Group behaviour is not an iOS 27 matter.
- Countdown: 91 rows, all `ok`, from 11-06 6:15 PM ET to 11-13 10:35 AM ET: 22 in the app (app_foreground, first
  on 11-06) and 69 in the widget extension (trigger system). It goes through the same `files.shared` in the app, and
  that fits the cause rather than contradicting it. The check fails only once scripts/ exists. While scripts/ does
  not exist, the root and the folder both keep `/private`, the check passes, and making the folder makes scripts/
  too. Countdown was the first premade to ask (11-06), so its folder was made. Every premade asking after that, for a
  folder not made yet, was refused: the four, first seen on 11-09. A Mac probe of the same call agrees (scripts/
  absent: equal; present: not equal).
- Quote and Habits: no runs file, and the manifest copied 6 files with none missing or failed, so the phone has no
  row for either one, ever. Both are Pro in build 4 (`TIER = "pro"`; pro-flags.json at d3d39da37 holds the 7 Pro
  premades). Without a Pro purchase the app's pass does not offer them (`offeredPremades`, includeLocked false), and
  a placed locked premade is skipped with no row by design (WidgetWriter: "A locked premade logs nothing: its face
  is the Pro card"; the extension does the same). So "no rows" is what a phone without Pro should show. It is a
  separate fault only if this phone has Pro (bought or granted) or the placed widget shows anything but the Pro
  card. The export cannot tell which. Not changed here.

draw and get Run log rows. If they say "Not drawn yet" with Pro, that is a new task.
