## T-4908 root cause (refusals per day 20 against a limit of 16.49)

1. The signal mostly counts the merge gate, not the guards. tools/bottleneck_watch.py's refusals source counts
   ops/metrics/main_gate.jsonl rows refused, host_refused and suite_refused: the gate's commit check saying no passing
   test run exists for exactly this content. That is the gate working, usually because main moved during the check. And
   one blocked commit writes up to three rows: on 11-18, 8 blocked commits wrote 12 rows (11-17: 6 wrote 9; 11-04..18:
   58 attempts, 71 rows).
2. The real guard refusals that rose on 11-18 share one cause: main moving during a land. The gate then refuses the
   commit, and the worker's next step, rebasing its private copy onto main, is refused by the GitHub-sync rule.
3. Fix, big picture: (a) T-4911 (landed 11-18) has the gate bring main's moves into the copy itself (land --from, settle),
   so no rebase is needed; packets must say so (board line B1). (b) The signal counts one per blocked commit and keeps the
   gate's checks apart from guard refusals, read from the session streams (board line B5). (c) The guard proposal (<span title="The starting recipe a lane uses to look for ideas. G2, for example, starts from public datasets.">G1</span>)
   lets a private copy rebase onto local main and stops reading text as a sync.
