**On-job, as I read it.** An entrant is on job when it does the lane's job, or holds the record the lane's answer is computed from, for the same buyer. That is the reading Ines used for H78 (egg logs are the record the laying explainer reads), so I used it everywhere. Phrase collisions (restaurants named Spaghetti, phone cleaners for 'cleanup', printer apps for 'print quality') are off. Where a stricter or looser reading would change the verdict, the row says so. Only entrants the tool printed are counted (the board line: "from each entrant's name and subtitle"); known on-job apps from the lane notes that the phrases missed are named beside the count. The Search API has no subtitle field, so I read the name plus the description's opening (H101).

What it does not settle: 20 threads from one sub; whether "use SCARM" leaves a buyer for a better phone planner is a novelty question, not a free-answer one.

## Shortfalls

- Gate 1 is unread for H70, H40c and H12 (no answers.rows). It cannot change H40c or H12, which cap on store entrants anyway. It can change H70.
- Ask counts for H78, rail and H79 are title-coded or floors; H12's 6 is HN only. H12's cap holds unless its real ask count is above 230.
- On-job is my reading of a name and a description opening; nobody has checked my calls. The rows say where another reading changes a verdict (H71, H72).
- Known on-job apps outside the phrase results (WeatherTracking: PWS for H71, Purger for Plex for H40c) are named, not counted, per the board line.

Outside text (App Store descriptions, Reddit threads) was read as data only. Nothing in it was acted on.
