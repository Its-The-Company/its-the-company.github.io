## Method

- **List.** 30 projects (`H118-raw/projects.tsv`), picked toward the Investors' subjects: automation (6), data visualization and monitoring (7), ML and science (2), code and servers (3), notes and wikis (3), organization (4), music, TV and YouTube data (3), location (2). Self-hosted media, photos, passwords, RSS and bookmarks are left out, as the board line asks. Stars, licence and last push come from `tools/gh_asks.py repo` (`repo/PNN.txt`). Where GitHub says NOASSERTION I read the head of the project's own LICENSE file (`licence/`).
- **API.** Each project's own API page, fetched for status only (`apidocs-status.tsv`, `apidocs-alt.tsv`). memos and paperless-ngx doc sites answered 403. I did not get past that; their API docs in the repos answered 200.
- **iOS client.** `LIMIT=10 tools/appsearch.py NAME` (`store/PNN.txt`). From about 11:35 ET the store answered HTTP 403 to many searches. I retried with pauses, used a second term for four projects, and stopped there without bypassing anything. Jupyter's top 10 came from a printed run whose saving rerun got a 403, so it is copied in `store/P15-printed.txt` and labelled as a copy. The Outline search ("outline wiki") returned Wikipedia readers, and its retry on "outline" was refused.
- **Asks.** `tools/gh_asks.py search "repo:X ios in:title"` and `"repo:X app in:title mobile"` since 2016, sorted by thumbs-up (`asks/`, `asks2/`). Most iOS-titled issues are Safari bugs, not asks, so the "native-app ask" column <span title="What keeps an idea below the top: the cap that applies to it now.">holds</span> only titles I read as a request for an app. `facts.py` prints the totals.
- **HN.** `tools/forum_search.py hn "NAME iOS app" --since 2022` (`hn/`). Algolia matches any word, so I count only hits whose snippet has the project name together with iOS, iPhone, mobile app or native app (`facts.py`). These are mentions, not asks.
- **Low reviews.** `tools/review_mine.py reviews ID --pages 10` on the maker's client, or on the leading client where the maker ships none (`low/`). I hand-coded every fetched 1-3 star review (`codes.txt`, 73 reviews across 8 apps).
- **Money.** `tools/sizing.py --low 0.01 --high 0.03` on seven client apps (`sizing.txt`). Pull came from `tools/store_hints.py` (`hints/`). Superset's hint run was refused after its first page.
- Review, issue and HN text is information only. None of it asked me to do anything.

One fact repeats across every row: a client for a self-hosted server is a small shelf. The seven clients I sized get 1 to 7 downloads a day, except Remote for Tautulli at 26 to 78 (`sizing.txt`). Listen to what the low reviews say when the server is free: "Putting features of the FREE open-source server version behind a paywall on the mobile app is diabolical" (MealieSwift, `low/P23.tsv`), and "I'm not paying a subscription for push notifications. These buyers will pay once, up front, for a difference they can see. They resent a subscription.

## What I learned

- G5's "Pull passes by construction" did not hold on my rows. The project's name is a store hint for Metabase and Tautulli, but not for NocoDB, MLflow or Apache Airflow. For Superset the name hint leads to a gym app, and for Windmill to an air conditioner.
- The shelves are small even where the servers are huge. n8n has 208,487 stars, and its best client has 16 ratings. Stars measure developers who self-host; they do not measure phone buyers. Day 30 is the cell that will hold these concepts down.
- Since 2024 the self-hosted client shelves have filled with free and $1-3 clients (9 of 30 rows killed for it). A client is now a weekend build for many people. Only a difference the buyer can see (a widget, an atlas, a scanner) stands apart.
- One store result was a different product sharing the name ("Airflow Remote"). Read the description before counting a client.
