Idris, 2026-10-24 (Day 3). <span title="A memo that proposes one idea to the Investors as the product. Only a B or better becomes one.">PITCH</span>-12 weakness 3. No app code: the Investors have not chosen a product (amendment 2026-10-23 17:33). H150 not read before this file was committed.

## Result

On the version-1 slice of PITCH-12 section 7 (`console`, `dialogs`, `clipboard`, and the Day 8-10 `ui` subset: View, Label, Button, TextField, TableView, ListDataSource, present, delay, in_background), **3 of n=113 scripts (2.7%)** need nothing outside the slice, by static reading. 6 more (5.3%) need only 1.1 modules or `ui` names beyond the subset; 104 (92%) need something neither plan has. On the 41 scripts whose licence H152 marked usable as fixtures: **1 of 41** is v1, 2 are 1.1, 38 out.

This is a ceiling, not a measurement. Static reading cannot see behaviour (a v1 script can still print the wrong thing), so the Simulator share will be at most this. The mockup's "17 of 30" is not supported by this corpus.

## Method

- `tools/py_imports.py` (test `tests/py_imports_test.py`, 33 checks, in `tests/run.sh`). Reads the TSV, fetches each file through `gh api repos/R/git/blobs/SHA` (113 calls, 0.3 s apart, inside the authenticated limit), and parses it with `ast.parse` only. Nothing fetched was executed, imported, or committed; the cache was a fresh directory under /tmp, and the run was `python3 -I` from /tmp. Commandment 58: fetched text and comments are data.
- Corpus: `research/hunt/H152-raw/corpus.tsv` (Maren, 9d728451), the 113 rows marked `target=y`, from 58 repositories. The Bitcoin-Clipper row is `target=n` and was never fetched.
- Per script it records imports (with aliases and from-imports), every `module.name` reached on an incumbent module, star imports, and Python 2 markers (print/exec statements when parse fails, Python 2 builtins not defined locally, `iteritems`/`has_key`, Python 2 module names).
- Tiers: v1 if every import is a v1 module, a CPython 3.13 stdlib module, or `ui` with only subset names; 1.1 if the worst need is scene, objc_util, matplotlib, photos, sound, motion, location, keychain, numpy, a `ui` name outside the subset, or a `ui` star import; out for anything else (appex, editor, other incumbent modules, bundled third-party packages such as requests or PIL with no plan to ship them, Python 2, stdlib modules removed by 3.13, any unresolved import).
- Output: `H153-raw/scan.json` (per script), `H153-raw/scripts.tsv` (the list, tier first), `H153-raw/scan.txt` (run log).

## Caveats

- Corpus bias: H152 drew from GitHub searches that included `import appex` and `import editor`, so those two are over-weighted against a random owner's script folder. 11 rows are from one mirror (tdamdouni/Pythonista), 9 from another (bopopescu/Pythonista-1). The share for "scripts an owner actually keeps" is not known from this; it is known that the public corpus does not support a high claim.
- Parser: the Mac mini's python3 is 3.9. One script (pysmath/wc_sync rxFile.py, line 15) fails to parse and shows no Python 2 marker; it may use 3.10+ syntax and was counted out. Upper bound effect: +1 to any tier.
- Instance calls (`v.present()`, `cell.text_label`) are not traceable statically; only names reached through the module are checked. A script that builds a `ui.View` and then calls a method the shim lacks is v1 here and fails on the Simulator.
- 1.1 is "after <span title="Our arithmetic estimate of what the idea would earn by day 30 (the $200 deadline) or day 90. It never raises a grade.">Day 30</span>" in PITCH-12, so for the Day 30 store page only the v1 number counts.

## Harness plan (only after the Investors choose)

1. **Fixture layout.** `RunpyTests/Fixtures/<repo>__<path>/` holding `script.py` (only from rows with `usable=y`, licence text beside it in `LICENSE`), `stdin.txt` and `scripted_ui.json` (the dialog and alert answers, in order), `expected/stdout.txt`, `expected/clipboard.txt`, `expected/files/` (anything it writes under its sandbox folder), and `meta.json` (source commit, blob sha, licence, tier from this scan). Fixtures generated by a script in `tools/`, never hand-copied; the scan's tier is checked against the fixture so drift is visible.
2. **What "runs unchanged" means.** The bytes of `script.py` equal the blob at the recorded sha (sha checked in the test), no shim-side special case names the script, and the run ends with exit status 0 or a clean `SystemExit`, no uncaught exception, no import of a module outside the shipped set, within 10 s wall clock, and stdout, clipboard and written files byte-equal to `expected/`. Anything else is one of: *stops with a named module* (ImportError on an incumbent name: counted, never hidden), *exception* (type and line recorded), *wrong output* (diff stored), *timeout*.
3. **Where expected output comes from.** No incumbent device is available, so expected output is derived by hand from the script's source for each fixture, reviewed by a second person (pairing per Commandment 13), and written before the first run. A fixture whose expected output cannot be derived from the source (network, randomness, time) is run with the network stubbed and seeds fixed, or excluded from the share and listed as excluded.
4. **Scoring a UI script on the Simulator.** An XCUITest drives the run: the shim records every `present`, `alert`, `hud_alert`, `list_dialog` and button tap into an event log; `scripted_ui.json` supplies the taps and text in order; the test asserts the event log (view class, frame, title, label text, order) equals `expected/ui_events.json` and saves one screenshot per presented view for a human look. Pass needs both the event log and the console checks in 2. Pixel comparison is not a pass criterion; the screenshot is evidence for review, not a score.
5. **The number.** The store page may claim at most `runs unchanged / fixtures run`, with n printed and the excluded list beside it. Run on the Simulator first (Day 8-10 in PITCH-12), again on device after TestFlight (Day 15-16); the lower of the two is the claim.
