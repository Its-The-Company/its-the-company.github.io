No patent status can be read from USPTO from this machine without a human check or a sign-up. PatentsView now lives inside USPTO's Open Data Portal (ODP). Its pages load behind an AWS WAF challenge script, and ODP's API answers "Unauthorized" without an API key. A key needs a MyUSPTO account, and only the Investors can open one (Commandment 7: no sign-ups, no bypassing a human check). The <span title="One numbered piece of research into one area of ideas. Each lane has its own file.">lane</span> rule says status is read from USPTO and never assumed, and a live patent is a <span title="A test written in advance. If it fires, we drop the idea.">kill</span>, so no concept may carry a letter until that read is possible. An <span title="A GitHub issue asking the Investors for something that is blocking work.">Urgent Request</span> is owed (section 4). I ran the <span title="The App Store results a buyer sees for a search phrase. The top 10 is the first ten, dated the day we read them.">shelf</span> half for four gadget jobs (section 3), so the lane resumes at the patent step.

## 2. PatentsView's terms, quoted

From PatentsView's own GitHub organization, the README of its API wrapper (https://github.com/PatentsView/PatentsView-APIWrapper#license, read 2026-10-24 15:17 ET, saved as H158-raw/readme-PatentsView-APIWrapper.md):

> "Users are free to use, share, or adapt the material for any purpose, subject to the standards of the Creative Commons Attribution 4.0 International License."

So the board line's "public domain" is wrong by PatentsView's own words. The data is CC BY 4.0: commercial use is allowed with attribution. The terms page on patentsview.org now redirects into ODP (section 1), so this is the only text of the publisher's terms I could read today. The status of the patent documents themselves as US government works is a separate question, and I did not read it here. No legal opinion is given.

## 4. Urgent Request owed (text for the Operator to file as a GitHub issue)

Title: H158 blocked: USPTO patent status cannot be read without an ODP API key.

Body: The expired-patent lane (H158) has to read each patent's status from USPTO. PatentsView has moved into USPTO's Open Data Portal. Its pages sit behind an AWS WAF challenge, and its API answers "Unauthorized" without a key. A key needs a MyUSPTO account, which only you can open. Options: (1) open a MyUSPTO account and an ODP API key, and give the key to the Operator outside the repository; (2) rule that Google Patents' legal-status line (dated and quoted, with USPTO's patent number and grant date cited) may stand in for the USPTO read; (3) drop the lane. I recommend 1: a wrong "expired" is a kill we would not see until late. Other work continues meanwhile.
