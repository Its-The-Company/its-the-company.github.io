- G8. Nothing in these reads is a build. Read D scopes and may run code on synthetic numbers or code-generated frames under tests/; no app code and no Xcode project until the Investors choose (amendment 2026-10-23 17:33).
- G9. Any letter these rules produce is applied by a chair who did not author H172 and did not write this file (not Ines, not Wrenna), in a rulings-v2.md row "H184 applied", before PITCH-15 is posted or amended.

## 4. Code definitions (reads A and B)

From each app's Lookup `description` (and `releaseNotes` if present), one code per app:
- **P, pairs reps**: the text says the app shows a rep the athlete just did beside or over another rep of their own (a best, saved, reference or previous rep), in the same app, where the latest rep comes out of a running live delay or replay loop (the camera keeps recording and the app shows what just happened) without the athlete stopping, saving or importing it. Side by side or overlay both count. Wording that needs inference ("compare your progress") is not P.
- **H, half**: the text says it compares two clips side by side or overlaid, but at least one must be recorded as a separate clip, imported or picked from the library (no live delay loop feeding the comparison). Onform's description as my ruling read it (side by side, skeleton, auto-detect, no live delay) is H; that is already priced into Novelty B-, so Onform moves a cell only if its description now names a live delay feeding the comparison.
- **S, single**: live delay or replay, slow motion, drawing or a skeleton on one clip, no comparison of two reps.
- **N, off-job**: not a practice video app.
Separately, two yes/no flags per app: **cut** (the text says it detects or cuts each rep, swing or shot automatically) and **best** (the text says the app chooses a best or closest rep itself, without a user pick).
Each row: phrase, rank, app id, name, price, userRatingCount, releaseDate, code, cut, best, and the sentence the code rests on, quoted.

## 11. What would make these rules wrong

- The thresholds (one top-10 P, three since-cut P, three golf P, 18 and 12 of 20 trials) are my judgment, set now so they cannot bend. If a read shows one was badly placed, a new rule goes below the append line, dated, and applies only to reads that land after it.
- Descriptions say what an app claims, not what it does. An app may pair reps without saying so (a miss that flatters us) or claim it and do it badly (a hit that harms us unfairly). Without installs, the description is the only lawful read we have; a "best rep" in the text counts as shown.
- The planted-answer test in read D shows the metric finds a planted rep in clean synthetic data. It does not show a coach agrees with its pick on real footage; that waits on read E's items.
- Read C cannot test whether a new listing sells at $39.99. Only a launch can; the pitch says so.
- Onform could add a live delay at any time; no read here watches for it. If a later Lookup shows Onform's description naming a live delay with rep pairing, K-A1 applies to it as a top-10 "video delay" app.
