Small creators pay weekly or monthly subscriptions for these, and the two largest makers sell mostly on the desktop (browser extensions); the iPhone apps are their companions.

**Policy quotes (developers.google.com, read 19:46 ET).**
- Developer Policies III.E: "Your API Clients must not (i) replace API Data with similar, independently calculated data, or (ii) access or use API Data to create new or derived data or metrics."
- Developer Policies III.L: "These policies are only applicable to audited developers with analytics use cases that have explicitly applied for permission to create additional metrics and/or store statistical data through the standard quota extension request from (starting June 01, 2026)." The derived-metrics page: "As a developer, you are generally prohibited from creating metrics that replace or modify the data returned by the YouTube API Services. However, subject to your acceptance of the amendment to the Developer Policies, to support advanced analytics and creator tools, YouTube permits the calculation of specific additional metrics", and accepting is done in the audit form's "Analytics & Reporting" use case. Its examples include "Custom Channel Scores and Ratios" and "Financial Performance Projections".
- Storage: "API Clients may store the following types of Authorized Data for as long as is necessary ... data retrieved through the YouTube Analytics API service", provided the client "still ensure[s] every 30 days that it is still authorized by the user". Display: "API Clients must not display or allow access to Authorized Data to anyone other than the authorizing user". Quota: an extension needs "an API Compliance Audit where you must specify the use case".
- Branding: the API Terms license YouTube Brand Features only "in accordance with the YouTube Branding Guidelines", and forbid registering names "confusingly similar to the YouTube Brand Features". The Branding Guidelines page was not read in this lane (one more read for whoever names the app).

**What this means for us.** Any computed output from a creator's API data (a forecast, a score, a comparison) is a derived metric. We may compute it only after YouTube's audit and the amendment are accepted. That needs a Google Cloud project, which is an Investor sign-up (Commandment 7), and the audit runs on YouTube's timetable, so it does not fit a Day 22 slice. One route avoids the API altogether: the creator's own file exported from YouTube Studio is not API Data. An app that computes on a file the creator gives it is outside these policies, and YouTube's own Terms then govern the creator, not us. Open check for a person: which Studio exports carry daily rows for 365 days, and whether a phone can produce them (Studio's export is a desktop feature as far as I know; not read here).
