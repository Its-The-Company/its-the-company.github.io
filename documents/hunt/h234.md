## 0. Keep and kill rules, written before the first fetch (committed before H234-raw/bin/gate.py exists)

`python3 rules/lookup.py 7` was run in this session at 03:29 ET (`date`), before any subject was named. Commandment 7 areas near this subject: children under 13 (a school family-tree project, a child's route map); no concept is sold for or to children. Genealogy here is names, dates and relationships only: no DNA, no health history, no medical pedigree (medical). Org charts draw roles only: no pay, grades or ratings (finance, refill-27 H228 extra by analogy).

Commandment 6, living people: a GEDCOM or an org-chart spreadsheet holds living people's names and dates. Every concept runs on the device; the file is never uploaded by the app; the printable output is a PDF the user sends where they choose, and the concept must offer to hide living people (GEDCOM: no death event and born within 100 years). A concept that needs a server to lay out the file is killed at Fit.

### 0.1 Concepts, fixed now (algorithm by name, input the buyer holds, output)

- **K1 family wall chart from GEDCOM.** Input: the user's own GEDCOM export (any genealogy program writes one). Algorithm: layered (Sugiyama) layout of a family graph with marriages as nodes: generation layering, crossing minimisation over pedigree collapse and multiple spouses, then horizontal compaction; split into poster pages (bin packing of page tiles). Output: a pedigree, descendant or hourglass chart as a print-sized vector PDF.
- **K2 transit-style map of my own routes.** Input: the user's own GPX tracks (walks, runs, rides). Algorithm: map-match tracks to shared segments, then octilinear schematic layout (the metro-map problem, mixed-integer or local-search form) with label placement. Output: a metro-style poster of the user's own route network, one line per regular route.
- **K3 many-span timeline from a spreadsheet.** Input: the user's own CSV or XLSX of start/end spans (a family history, a project list, a reading or travel record). Algorithm: interval-graph colouring for lane assignment, then label placement without overlap and lane order to cut crossings of connector lines. Output: a dense vector timeline PDF.
- **K4 org or seating chart from a spreadsheet.** Input: the user's own sheet of name, role, reports-to (or table, guest). Algorithm: tidy tree drawing (Reingold-Tilford / Walker) with compaction for wide levels and page splitting; for seating, circle packing of tables on a floor plan (the drawing only; H228 owns the seating optimisation). Output: a vector chart PDF.

### 0.3 Two documents before the first fetch of each host, gated in code

`H234-raw/bin/gate.py` (written after this commit) fetches only through tools/terms_guard.py. Per host: robots.txt first (saved under H234-raw/robots/, matched by tools/robots_rules.py for User-agent *); a robots.txt that is not HTTP 200 or 404 is "robots unverified" and nothing else is read on that host. Then the terms at the usual paths; if none answers, one disclosed home-page fetch (if robots allows /) to find a link whose text or href says terms, and that link only. Terms are cleared in code only when the saved terms text has no sentence on robots, automation, scraping, crawling, spiders, data mining or harvesting; a host with such a sentence is cleared only when I quote the sentence in section 1 and write the host into H234-raw/terms/weighed.tsv with the reason, after reading every clause, not only the robot words (H210 lesson). Terms not found is a G2 gap: no page read. A fetch script refuses on its own robots verdict (H215 lesson).

Pages per cleared host: the home page, then up to 3 links from it whose href or text names price, pricing, chart, poster, route, timeline or org chart. Nothing signed-in, no checkout, no upload of any file.

### 0.6 The T1 answer and the print-or-layout question (refill-28 section 5)

Per concept: does the buyer pay for the layout, or only for the printing? Read from the paid service's own page: if it lays out from the customer's file (a design or chart-making fee, or a price that includes layout), the buyer pays for layout; if it prints a file the buyer made elsewhere, it is print only, and the concept's money is the print margin it does not take. T1 = a layout from the buyer's own file that no free rival read draws; a rival page not read is "unread", and T1 is open, never a pass.
