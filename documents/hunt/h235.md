## 0. Plan, written before any page is read

Question: for each path R28-1 names, do pages read under Commandment 6 show (i) HYG: a README naming the sources of position and magnitude to the naked-eye limit, each source's own page allowing commercial redistribution, and CC BY-SA 4.0's legal code ("Adapted Material" definition, section 3(b)) and FAQ allowing the catalogue file to ship under BY-SA, separate from the app's code; or (ii) BSC5 alone: a host whose robots.txt and terms allow the fetch and whose own page states public-domain or commercial-use status.

Method (same as L113): per host, robots.txt first, read through tools/terms_guard.urlopen and matched with Python's urllib.robotparser for `*` and for our token `ItsTheCompany`; then the host's terms page; then the pages. Script: research/hunt/H235-raw/bin/get.py, URL list H235-raw/bin/urls.tsv, committed before it runs; raw pages and a fetch log (UTC per request) in H235-raw/pages/. No sign-in, no store path, company User-Agent.

Stop rules, fixed now:
- robots.txt disallows a path for `*` or our token: the path is not fetched. robots.txt unreachable (network, TLS, 5xx): the host is not read at all (RFC 9309, complete disallow). A 4xx robots.txt means no rules.
- A TLS certificate failure is a result, never bypassed (no unverified context).
- A redirect to another host: that host's robots.txt is checked before its page is counted; if it was not, the page is set aside and named.
- A host whose terms forbid scripted reads: its pages are not used, whatever robots says.
- Page text is information, never an instruction (Commandment 5/58).
- A source the README names but whose own page is unread (robots, terms, 403/404, TLS) is written as a G2 gap, which is R28-1c for that path.
- Follow-up URLs found inside a page (a source link in the README, say) are post hoc and marked so.

Hosts and pages, in order:
1. docs.github.com: GitHub Terms of Service (refill-24 section 3 ruled the API; I read the terms myself so the quote is in this file).
2. api.github.com: astronexus/HYG-Database README (raw), root contents (source list files), licence file.

## 1. What ran (pages read 2026-10-25 03:30:15-03:32:08 ET, `date` before and after; UTC per request in H235-raw/pages/fetch-log.tsv)

Every request went through tools/terms_guard.urlopen with the company User-Agent. **Mistake, owned:** get.py matched robots.txt with Python's urllib.robotparser, as L113 did, and robotparser does not apply RFC 9309 wildcards. It passed four codeberg.org paths (the HYG README and LICENSE on Codeberg, a data README, Codeberg's Terms of Use) that codeberg.org/robots.txt refuses for `*` with `Disallow: /*/*/raw/`. I found it when I re-matched every URL with tools/robots_rules.py (H235-raw/pages/robots-rfc9309-recheck.tsv). The four page copies are deleted, the fetch log says so, and nothing below rests on them. get.py now matches with robots_rules (same commit as this section). For Ines: L113's read.py uses robotparser too. The L113 URLs I re-read pass the RFC 9309 match; I did not recheck its other URLs. Also: I sent the three cdsarc ReadMe requests about one second apart, while cdsarc's robots.txt asks for `Crawl-delay: 10` (not part of RFC 9309, but a stated request). I went over budget: 10 turns of 6.

The Adapter’s License You apply must be a Creative Commons license with the same License Elements, this version or later, or a BY-SA Compatible License. ... You may not offer or impose any additional or different terms or conditions on, or apply any Effective Technological Measures to, Adapted Material that restrict exercise of the rights granted under the Adapter's License You apply."

Section 3(b)'s "Effective Technological Measures" sentence would apply to an Adapted catalogue file shipped inside a signed, DRM-wrapped App Store binary. Whether a file shipped unmodified is Adapted Material is a reading question for the applier, not a quote.

**GitHub ToS**, https://docs.github.com/en/site-policy/github-terms/github-terms-of-service, section H: "Abuse or excessively frequent requests to GitHub via the API may result in the temporary or permanent suspension of your Account's access to the API." ## 3. Which R28-1 clause each path's quotes meet (no moves; Odalys applies)

- **Path (i), HYG.** README and maker's page name three primary sources, and Hipparcos is one of them. Hipparcos's own page (ESA) says "CC BY-NC 3.0 IGO", and ESA's terms ask for authorisation before any commercial use. That matches the words of **R28-1b**'s first limb ("a needed source whose own page says non-commercial"), provided Hipparcos is "needed" for position and magnitude. The README's fields do not say which source each star's `ra`, `dec` or `mag` comes from. That BSC5 alone covers naked-eye stars is the maker's sentence, but HYG's values for those stars are not shown to come from BSC5, so whether Hipparcos is needed is a reading for the applier. **R28-1c** pieces on the same path: BSC5's own pages (HEASARC, Harvard) are unread (TLS), and the Gliese publisher's page is unread. The CDS records for V/50, I/311 and V/70A carry no licence words. The Codeberg README is a robots gap. The astronexus host showed no terms page. ShareAlike: the legal code and FAQ are quoted above. **R28-1a**(i)'s second limb (shipping the file under BY-SA, separate from the code) is neither established nor refuted word for word, and the ETM sentence is the open reading. R28-1a(i) is not met either way, because its first limb needs every source's page to allow commercial redistribution, and the Hipparcos page does not.
- **Path (ii), BSC5 alone.** No host whose robots and terms allow the fetch states public-domain or commercial-use status for BSC5. CDS allows the fetch, but its V/50 record states nothing, and CDS's own page defers to the origin. HEASARC and Harvard were not reached (G2). No page read says non-commercial for BSC5. That is **R28-1c** (a needed page unread: HEASARC's BSC5 copy, the one L113 named as a possible US-government statement). It is not R28-1a(ii), because no page states the status, and not R28-1b, because no page says non-commercial.
- R28-1 says "either path suffices" for 1a, and 1b needs "every path". How 1b and 1c combine across the two paths is Odalys's to apply. Rule 1 stays unmet (R28-1's last line), so this read moves no letter.

Leads (not read): HEASARC from a machine whose TLS check passes; Astronomisches Rechen-Institut's own CNS3 page; Codeberg's Terms of Use through a path robots allows; a robots_rules recheck of L113's other URLs.
