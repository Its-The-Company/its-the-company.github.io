Generator G62 (research/hunt/<span title="A numbered batch of planned work, with its own plan file.">refill</span>-29.md section 5): owners of paid desktop and web products vote, on the maker's own forum, for computations on their own data that the product does not do; where a separate phone app could do that from an export or a documented API, the vote count is a measured demand floor. A topic in those areas is coded X before clustering (C7), whatever it asks.

## 0. Rules written before the first fetch (written 04:14 ET; committed alone, before any script or read)

**The fetch rule in code.** Every request goes through `H238-raw/bin/get.py` (H231's guarded fetcher with paths changed): it opens URLs only through `terms_guard.fetch`, and before that stops with exit 2 when (a) the host's robots.txt, saved by `get.py robots HOST`, disallows the path for `*`, `ClaudeBot` or `anthropic-ai` (matched by tools/robots_rules.py, never urllib.robotparser), or (b) in `page` mode, the host's verdict in `H238-raw/terms-verdicts.tsv` is not `permits` or `none`. The vote read is `H238-raw/bin/votes.py`, which runs the same two checks on every list URL it will request and only then calls `tools/discourse_votes.py BASE PATH --since 2025-10-25 --top 40` (which itself fetches through terms_guard). `python3 tools/lane_fetch_check.py --lane H238` runs before the first fetch; its line is kept in section 1. A robots disallow or a terms bar is a result, written "refused", never 0, and never worked around.

**Terms rule, fixed now.** Each forum's own terms page (Discourse `/tos`, or the maker's linked terms) is read by hand before any list fetch, and the governing clause is quoted in section 1. Verdict `forbids` when the terms bar robots, spiders, scrapers or any automated access without exception. Where the terms carry the Discourse default clause (no access "by any means other than our publicly supported interfaces (for example, 'scraping' ...)"), the anonymous topic-list JSON that the forum's own page loads is read as the public interface, at one request per 3 s and at most the pages the tool walks; that verdict is written `permits (public JSON, default clause)` with the clause quoted, and is flagged to the <span title="The worker who reads both graders and decides. The decision, a ruling, is one row in the rulings file.">chair</span> to overrule at <span title="The rule that decides whether an idea gets two blind graders now, waits (park), or stops.">T1</span>. No login, no API key, no search endpoint.

**Paid, with price on the product's own page.** Checked before the forum counts: one guarded fetch of the maker's own pricing page; a price not in the served HTML is written so, and the forum is replaced.

Music-making products are out (none listed). **Selection, at most 6 forums:** round by round across the subjects in order, the first unused candidate in each subject that passes robots, terms and the price check: round 1 is Obsidian, Keyboard Maestro, Grafana, (science gap), Plex; round 2 starts with DEVONthink, which makes six. A candidate that fails is replaced by the next in its own subject, in the same round; if a subject runs out, the next round fills the place.

**Which category.** Per forum, one `discourse_votes.py BASE --categories` call; the category read is the one named feature requests, ideas, suggestions or wishlist (the first such in the list if several); if none exists the forum is written "no request category" and replaced. Votes are the topic-voting plugin's `vote_count`; where a forum has no voting plugin the tool prints `-`, and that forum's clusters count topics only (the 25-vote branch is not used there; likes are recorded, not counted as votes).

**Codes (refill-29.md section 5), one per topic, hand-read from the title, tags and the list row; a topic whose title does not state what it asks is coded X (no topic page is fetched to rescue it):**
- **A:** asks for a computation on the owner's own data or files that the product does not do, where a separate phone app could do it from an export or a documented API.
- **B:** asks for a mobile client or port only.
- **X:** everything else (UI, sync, bugs, integrations without a computation, C7 areas).

**Cluster cut.** Code-A topics are clustered by the computation asked (same input, same output), across forums. A cluster passes with 3 or more topics, or 25 or more votes summed, created since 2025-10-25. At most 4 <span title="One product idea inside a lane. C1 is the lane&#x27;s first idea.">concepts</span> go on, in order of votes summed, then topics.
