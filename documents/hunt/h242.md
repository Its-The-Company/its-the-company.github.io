## 0. Section 0 (written 2026-10-25 04:18 ET by `date`, before any fetch and before any <span title="One numbered piece of research into one area of ideas. Each lane has its own file.">lane</span> script)

**Commandments.** `python3 rules/lookup.py 7` was run before this section. A request in a C7 area (finance, medical or health, legal, gambling, adult, weapons and substances, children under 13, political campaigning) or one that needs other people's personal data, payments or outreach (C6, C10, C58) is coded OUT before clustering.

**Hosts and terms, in this order, each before its first data fetch, every request through tools/terms_guard.py:**
1. GitHub Terms of Service (docs.github.com/en/site-policy/github-terms/github-terms-of-service, section H, API terms) and GitHub Acceptable Use Policies (docs.github.com/en/site-policy/acceptable-use-policies/github-acceptable-use-policies, the information-usage section), quoted in section 1. If they bar this use, the lane stops at section 1, written refused.
2. Each repo's CONTRIBUTING file (and code of conduct where CONTRIBUTING links one), read once through the API before that repo's issue search; where it routes feature requests elsewhere, that is quoted.
3. Any price page: its host's robots.txt and terms first. A host that bars the read is a <span title="A figure we could not read because the source&#x27;s terms or robots file do not let our software read it. It never lowers a grade.">G2 gap</span>.
No Stack Exchange API. No Hacker News (held pending a terms <span title="The worker who reads both graders and decides. The decision, a ruling, is one row in the rulings file.">ruling</span>). No Reddit.

**Repos (<span title="A measured fact that holds a grade below a letter, however good the rest is.">cap</span> 6), one per subject, in this order; each must show at least 1,000 stars, not archived, pushed since 2025-10-25 on `gh_asks.py repo`. A repo that fails is replaced by its alternate, named here; no alternate means the subject is written unread.**

**Issue queries (two per repo, tools/gh_asks.py search, --since 2015-01-01 so creation date does not filter, --top 50, 7 s between calls):**
- Qa `repo:R is:closed reason:"not planned" closed:>=2025-10-25`
- Qb `repo:R is:closed label:wontfix closed:>=2025-10-25`
Union by URL. Raw output saved as printed in H242-raw/search-R#.txt.

**Discussions.** tools/gh_discussions.py (since 2025-10-25, 20 comments) only for a repo whose CONTRIBUTING sends feature requests to Discussions, at most 2 repos. A discussion counts as declined only where a maintainer's comment declines it in words, quoted.

**Thread read.** `gh_asks.py comments` (--chars 400) on union threads with 4 or more comments (5 distinct askers need the opener plus 4), most comments first, cap 40 threads. GitHub's unauthenticated core limit (60 an hour) is honoured: a 403 or 429 after the tool's one wait is refused, the lane stops reading threads, and the rest are written unread.

**Codes, by hand, in this order:**
- OUT: C6, C7, C10, C58 areas (above).
- X: not a feature request (bug, support, question, duplicate, crash, translation), a port to a platform, sync or hosting, a developer API, or a UI preference with no computed output.
- D: a declined feature request (closed not planned, wontfix or out of scope, closing words quoted) that is not A.
- A: a declined feature request for an output computed from the asker's own data (a number, schedule, plan, summary, chart, match or check), where the output is the point.

**Askers (R30-2).** Distinct accounts asking for the computation in their own words, in the opener or a comment. Not counted: maintainers (author association OWNER, MEMBER or COLLABORATOR), bots, reactions (recorded beside the thread), and "+1" comments with no words of their own. A thread qualifies with 5 or more distinct askers.

**Clusters and <span title="One product idea inside a lane. C1 is the lane&#x27;s first idea.">concepts</span>.** From qualifying A threads only, by the output asked for. One qualifying thread may make a concept (it already <span title="What keeps an idea below the top: the cap that applies to it now.">holds</span> 5 askers). At most 4 concepts.

**R29-2 demand, per concept.** Window 2026-07-27 to 2026-10-25. The venue is GitHub (these threads). Asks dated in the window are counted from the saved threads: 3 or more means met; 0 to 2 means <span title="An idea that reaches B or better but is held below B by a measured cap. No graders until a permitted reading lifts the cap.">parked</span> for need. No further queries are made in this lane.

**Money.** A paid product that does the job, named in a thread or the closest product the asker could buy, priced from its own page after that host's robots.txt and terms (cap 4 price pages). No readable price: "no priced good read".

**Stop.** Turn budget 10; at the budget the file is committed with an Open list. Result line last.

## 0a. Amendment to the thread read (written 2026-10-25 04:21 ET by `date`, after the searches and before any thread is read)

The searches returned 199 union threads, 119 with 4 or more comments. By title, almost all are bug reports closed "not planned" (crashes, sync failures, start-up faults), which GitHub's close reason also covers. Reading 40 threads would take 80 of the unauthenticated core limit's 60 an hour (two calls a thread). So the X code is applied from the title first where the title alone states a bug, crash, sync fault, platform build, UI placement or translation, and threads are read only where the title states a feature request that could be D or A. The 7 read, most comments first: super-productivity 6078 (start and due date), the GitHub-labels import thread, "Option to do multiple tasks at once", "More flexible recurring task planning"; ActivityWatch "Automatically export JSON on regular basis?", "I don't understand the time statistics", "Sync data from another time tracker". Every other candidate is coded X from its title in H242-raw/codes.tsv. Account names are replaced by a short hash in the saved threads (AUP section 7: public, non-personal information).

## 1. GitHub terms (read 04:19 ET through tools/terms_guard.py; H242-raw/terms/)

- Terms of Service, H. API Terms: "Abuse or excessively frequent requests to GitHub via the API may result in the temporary or permanent suspension of your Account's access to the API." "You may not use the API to download data or Content from GitHub for spamming purposes, including for the purposes of selling GitHub users' personal information". The section's own summary: "the rules for using GitHub's APIs, whether you are using the API for development or data collection."
- Acceptable Use Policies, 7. Information Usage Restrictions: "Researchers may use public, non-personal information from the Service for research purposes, only if any publications resulting from that research are open access." "Scraping does not refer to the collection of information through our API."
- Reading: not barred. Calls stayed inside the rate limits (core 6 repo and 14 thread calls unauthenticated, 12 search calls 7 s apart, 6 authenticated CONTRIBUTING reads), nothing is sold or sent to anyone, and account names are hashed in the saved threads. Whether a commercial company's market read counts as "research purposes" under AUP 7 is a question for the chair, not one I can settle; written here so it is on file.
