## 0. Sources, hosts, caps, codes (committed before any lane fetch)

**Query plan (only if the API host may be read).** One `search_query` per category, `cat:X AND submittedDate:[202501010000 TO 202610242359] AND (abs:"code is available" OR abs:"code available" OR abs:"github.com")`, `sortBy=relevance`, `max_results=50`: cs.CV, cs.CL, cs.HC, cs.IR, eess.SP, physics.data-an (6 calls), at the ToU's stated interval or 3 s if none is stated, whichever is longer. Metadata (Atom XML) only; no PDF, no e-print, no source.

**Seed codes (hand, from title and abstract).**
- **On-device:** D1 the abstract names a phone, mobile, edge or on-device run, or a model under 100 M parameters; D2 small enough to plausibly fit (stated size or FLOPs), not shown on a phone; D0 server-scale or unstated.
- **Buyer's own input:** I1 camera or photo library; I2 microphone recording analysed (not music creation); I3 text the buyer wrote; I4 files the buyer owns (PDF, video, GPS track); I0 none (benchmarks, others' data).

A seed is D1 or D2, I1-I4, CG or CO, and not X. - `python3 tools/lane_fetch_check.py --lane H265` before the first fetch: "1 scripts, 0 FAIL, 1 ok, 0 no fetch". Section 0 committed d46054f1 (06:39), before bin/get.py was written.
- **Terms located and quoted** (info.arxiv.org, robots 404; `H265-raw/terms/api-tou.html`, 85 KB, 06:40). "Terms of Use for arXiv APIs": "Our APIs include our OAI-PMH interface, RSS feeds, the legacy arXiv API, bulk data downloads, and SWORD bulk deposit API." "By using arXiv APIs, you are agreeing to the terms and conditions outlined on this page." Licence of what the lane would read: "You are free to use descriptive metadata about arXiv e-prints under the terms of the Creative Commons Universal (CC0 1.0) Public Domain Declaration." Papers themselves: "The redistribution of e-prints requires permission from the copyright holder." **Rate limit:** "When using the legacy APIs (including OAI-PMH, RSS, and the arXiv API), make no more than one request every three seconds, and limit requests to a single connection at a time. These limits may change in the future." The limits "apply to all of the machines under your control as a whole." The page also asks users to "respect limitations on use of arXiv APIs, including rate limits and authorization mechanisms". No date on the page in what I read.
- **User manual** (`terms/api-user-manual.html`, 148 KB, 06:40): "Please review the Terms of Use for arXiv APIs before using the arXiv API." Endpoint `http://export.arxiv.org/api/query`; "We recommend to refine queries which return more than 1,000 results"; "For bulk metadata harvesting ... the OAI-PMH interface is more suitable." No second rate figure.
- **API probe, refused before send** (06:40): terms_guard: "export.arxiv.org/robots.txt disallows this path for User-agent * (rule: Disallow: /; live copy read 2026-10-25 06:38), so it was not fetched". Nothing reached export.arxiv.org. The other two routes the ToU names are barred on arxiv.org too: `Disallow: /api` and `Disallow: /oai2` (same day's copy).
- **The conflict, stated plainly.** arXiv's API Terms of Use invite API use at one request per 3 s; the API host's own robots.txt bars every agent from every path. The company's gate (terms_guard, Commandment 6) treats robots as binding, and section 0 made a disallow a stop. I did not weigh one against the other; that is a terms ruling, like the HN one, and not the lane author's.

Fetches: 2 preflight locate + 2 terms pages + 0 sent by the probe = 4 of 25. Papers read: 0 of 40.
