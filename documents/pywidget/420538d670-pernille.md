Since then on main, one commit touches `lane.py`: 6d64e84bfe (T-4494 item 1). It does not touch `send_lane`, but it
changes the rule `send_lane` writes into: no "lane" key now means the widget lane (`DEFAULT_LANE = "widget"`), and
`LaneMirror` keeps a widget out only when the project's pywidget.json says something other than "widget". I read it
for that reason. It makes M1 worse, not better (below).

No Xcode run: nothing in this slice is Swift, and the Swift test that would matter does not exist yet.

## Verdict: PASS with findings

For one send, the function does what the handoff says, case by case, and the tests pin every case it lists. The
refactor of `scan_source` into `_imports` + `_first_per_line` keeps the old scan's behaviour (the 46 older tests in
the file are unchanged and green), and the parity test holding `DENIED_SUBMODULES | APP_ONLY_SUBMODULES` against
`LaneDeviceRouter.appOnlyModules` is the right kind of test. The step-1 finding for Ines is accurate and useful.

Nothing calls `send_lane` yet, so nothing here reaches a person or TestFlight. But M1 and M2 are in the decision
itself, and the Swift slice will inherit both the moment it wires the call. Fix them before that, not after.

## Findings

### M1. The "app" a send writes becomes a typed "app" on the next send, so a cleaned script never goes back

- Where: `lane.py:481-490` (`keep = typed is not None`; `if typed == "app": return ... "line": None`;
  `"write": None if keep else "app"`), and the handoff's Left items 2 and 3 (`ops/plans/T-0972-handoff.md:28-29`).
- The failure, probed: send 1, `import sqlite3` in a plain project (`typed=None`) gives
  `("app", write "app", name "sqlite3")`. The Swift half writes `"lane": "app"`. The person removes the import and
  sends again: `typed` is now `"app"`, so send 2 gives `("app", write None, line None)`. The widget stays in the app
  lane for good, and no line says why. `send_lane` cannot tell an "app" it wrote from one the person typed.
- Against: T-0972's own rule ("Clean: `lane: widget`"), and T-4280's, which T-4494 now applies to every sent script
  ("new script text sends it back"). Since 6d64e84bfe, `LaneMirror` (`pywidget/ios/App/Projects/LaneMirror.swift:11-12`)
  keeps a widget out exactly when pywidget.json says something other than "widget", so a written "app" is the one
  thing that pins it there.
- T-4494 also takes away the reason to write anything. No key now means "widget", so writing "widget" for a clean
  plain project changes nothing. Not writing at all also removes both of the handoff's step-1 problems: no full s7
  manifest in every plain project, and no silent change to a person's copy (ADR-001's Project row, T-4476).
- Fix (Idris, with Ines's <span title="The worker who reads both graders and decides. The decision, a ruling, is one row in the rulings file.">ruling</span> on T-0972's wording): the send stops writing the lane key. `send_lane` returns only
  `lane`, `name` and `line`: "app" means no mirror this send, plus the line; the person's key, if any, is read and
  never written. Ines rewords T-0972's "Clean: `lane: widget` in pywidget.json" against T-4494. The handoff's Left
  items 2-3 are rewritten to match, including whether T-4494's "mirror every sent script" and T-0972's "no mirror
  over a refused import" agree; as written they do not. Test: the two-send sequence above ends in "widget".
  Board: T-4656.

### M2. Import forms the extension answers NotAvailableHere still come out "widget" with no line

- Where: `lane.py:451` (`APP_ONLY_SUBMODULES`) and `:476-478` (the hit filter), and the parity test
  `test_lane.py:744-751`, which reads only `appOnlyModules`.
- The failure, probed, each giving `("widget", write "widget", name None)`:
  - `from pywidget import device` then `device.location.current()`;
  - `import pywidget.device` then `pywidget.device.pedometer...`;
  - `from pywidget.device import *`.
  `pywidget/device/__init__.py` imports `location` and `pedometer` eagerly, so all three load the app-only modules,
  just as `from pywidget.device import location` does, which is caught.
  - `from pywidget import net` then `net.request(...)`: `NetCall.appOnlyMethods = ["request"]`
    (`NetCall.swift:13`, landed 11-13 in a9108cc747, before this commit) and `LaneDevice.swift:38` answers it
    NotAvailableHere. The parity test cannot see this half of the router.
- Why it matters: T-4280's runtime move still catches these after one run in the extension, so the widget recovers.
  But the one thing T-0972 promises a person at send time (Ines 11-02: "it gets app and the same one line") does
  not happen for the most natural way to write the import, and the parity test says the sets agree when they do not.
- Fix (Idris): count any import of `pywidget.device` itself (plain, `from pywidget import device`, star) as app-only
  while its `__init__` loads both; for `net.request`, either scan `from pywidget.net import request` and
  `<name bound to pywidget.net>.request` attribute calls, or write down in the handoff that the send leaves methods
  to the runtime move. Then extend the parity test to read `NetCall.appOnlyMethods` and hold that decision.
  Board: T-4657.

### L1. "First import in source order" is not quite source order, and two mutants live

- Where: `lane.py:488` (`sorted(hits)[0][2]` on `(lineno, col_offset, name)`), `test_lane.py:728-730`.
- `import ssl, sqlite3` names `sqlite3`: both names share one node's line and column, so the tie goes to the
  alphabet. `scan_source` has the same tie-break (`:427`), so it is old behaviour, but the send's line names one
  import only, and it should be the one the person wrote first. The `sorted` -> `hits[0]` mutant survives because no
  test puts a nested import (walked later by `ast.walk`) above a top-level one; the `app_only` exact-match mutant
  survives because no test imports below an app-only module (`import pywidget.device.location.x`).
- Fix (Idris): break ties by position in the statement; add those three cases to `SendLaneTests`. Board: T-4658.

### L2. `typed=None` means both "no key" and `"lane": null`

- Where: `lane.py:459-481`, docstring "None when it holds none".
- Since T-4494, `"lane": null` keeps a widget out (`LaneMirror.swift:11-12`), and strict `lane_of` refuses it as
  `bad_lane`. A Swift caller that maps JSON null to `nil` gets "widget" and, as the code stands, writes "widget" over
  the person's null. If M1's fix stops all writes, what is left is the lane decision: null should come out like any
  other bad value ("app" plus the bad-lane line). Fix (Idris): a separate "absent" value, or a documented rule that
  the caller passes the raw JSON value, with one test. Board: T-4658.
