## Verdict: PASS with findings

The captions are the decided words. Shot 3 is "Every widget is / Python you can edit" (T-3345). iPad 1 is "Write a
widget and / see how it looks" (T-0173, PROPOSAL-003 s2.6, T-3345). Neither is new wording. Both stay draft App Store
copy for the Investors' pre-submission review: `creative/approved.md` item 8 leaves screenshots out of the voice
approval, and the file and the sheet say PROPOSAL. Every pixel is HTML, CSS or SVG written by the design scripts. The
fonts are the system SF and New York already used across the set. Nothing is generative, and no new outside asset
appears. The pane draws the tree that the code on screen builds (`widget_doc()` runs and validates it), so the shot
cannot show a widget the code would not make.

One finding is Medium. The shot claims a feature that is not built yet, and the gate that would pull it is not in
the data the set carries.

## Findings

### M1. iPad 1-split shows the editor preview pane, but its gates leave out gate P, and the pane is not built

- Where: `draw_store.py:263` (`gates=["G5"]`), `qa.json` (both 1-split entries), `capture-list.md:30` (the gate is in
  prose only), and the tick record's Plain sentence ("the widget preview beside the code, which ships in 1.0").
- What is true today: the plan's 11-04 chair note (item 5) puts the editor preview pane (T-0192 part A) in 1.0. No
  pane exists in `pywidget/ios` on main: a search for the pane's names finds only a comment in
  `App/Runtime/pywidget/context.py` and a WidgetKit test. `App/WidgetRunView.swift:10` says no screen starts a widget
  run of a user script yet (T-0191, T-0192). T-0192 has no done line in `log/board-archive.md`. The same note's
  Fallbacks name the preview pane as the second thing to move to 1.1 if time runs short.
- Why it matters (C6, App Store 2.3): the caption promises the one thing the pane does. PROPOSAL-003 s2.6 gave iPad 1
  "a new gate P" for exactly this, but SHOTS records only <span title="The starting recipe a lane uses to look for ideas. G2, for example, starts from public datasets.">G5</span>, the widget cut line. So `qa.json` and the sheet show the
  shot as resting on widgets alone. If the pane moves to 1.1, nothing in the set's data says this shot and its
  caption must revert. The done-note also states as fact something that is a plan. Reports are built from those notes.
- Fix (Maren): give 1-split `gates=["G5", "P"]` and regenerate `qa.json`. In `capture-list.md`, name P as "T-0192
  part A on main" next to the other gates. When the T-0261 note's "ships in 1.0" is carried into a report, it should
  read "planned for 1.0, not built yet". Board: T-4752.

### L1. The same files still describe the 5-free / 7-Pro model that the new claim retires

- Where: `draw_store.py:63` (`FREE = {1, 2, 3, 4, 5}`, "any other shown needs a Pro mark"); `capture-list.md:3` ("the
  first five in its order are free, seven are Pro") and `:6` ("premades 1 to 5"). The commit's new claim at
  `draw_store.py:249` says "all 12 free, #142 6a". `catalog.json` no longer fixes a tier per premade (tiers are read
  from pro-flags.json at run time).
- Not harmful as it stands. The check is stricter than the rule, and no shot draws premades 6 to 12. But the file
  contradicts itself. Under 6a the Pro mark that matters is the "Live with Pro" badge on a background-refresh premade,
  and the check does not look for that.
- Also: the claim at `:249` cites "Ines T-0261 ruling". The decision is T-3345, as the commit message and
  `capture-list.md:32` say.
- Fix (Maren, with T-4752 if convenient): reword FREE and the two capture-list lines to 6a, and fix the citation. No
  separate line.

### L2. The store pane no longer matches the spec's pane, and the spec says it is reused

- Where: `draw_store.py:219-225` builds the pane inline. `draw_ide.widget_preview_col` (`ide/draw_ide.py`, the s5.8
  pane) has a family switch and the "Entry 1 of 3" stepper. The store pane shows "Small" as text, with no stepper.
  `ide/spec.md:340` still says the store shot "reuses this pane".
- The dropped family switch has a reason in the docstring: the snippet declares only `systemSmall`, which is
  pywidget_ui's default. The dropped entry stepper has no stated reason. The shot shows less than the spec, so it is
  not misleading. But the two drawings will drift, and the Simulator capture (T-0556) will show whatever part A builds.
- Fix (Maren): reuse `widget_preview_col` with a parameter, or note the difference in spec.md s5.8. No separate line.

### L3. The status-bar date swap can fail silently

- Where: `draw_store.py:227-230`. `.replace("Sun 25 Oct", ...)` does nothing if `mockups/draw.py:207` ever changes its
  default date. The assert at `:229` checks only that the default bar is in the frame, not that the date was swapped.
  The status bar would then read a day that disagrees with "53 days" and QA would still pass.
- Fix: `assert "Sun 25 Oct" in` the default bar before replacing it, or pass the date into `status_bar`. No separate
  line.

### Info

- `capture-list.md:29` (from T-2374) and the new line at `:32` call the editor text "the Countdown premade's source"
  or "the Countdown source". It is a 20-line widget written in the editor (`draw_store.py:113-131`). The premade
  `pywidget/widgets/premade/countdown.py` is a different, larger file. The shot itself is consistent: a user project,
  `trip_countdown`, under "Write a widget". The capture route should open the snippet, not the premade.
- The tick record cites ec9c1cd698. It has the same patch as 69674bf488, so the evidence holds.
