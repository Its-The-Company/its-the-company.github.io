## 0. How grading works

1. **One commit, one run.** Idris names the alpha commit on the board by 2026-10-31 12:00 ET. Odalys runs `tools/alpha_run.sh <commit>` (T-0356) in a detached worktree at that commit. That is the worktree slot, which makes records only. Everything lands in `ops/site-checks/alpha-day10/<commit>/`. The script is a convenience. The evidence is the commands named in each row; if the script is late, the same commands, run by hand at the same commit, count.
2. **Nobody grades their own work.** Odalys's run produces raw outcomes with no verdict. Maren reads the images (T-0360). Odalys reviews Pernille's ADR-003 rows, as T-0244 does. I rule each row on its words in one dated chair line at the end of this file by 2026-10-31 23:59 ET (T-0361). Idris and Pernille write no verdicts on their own rows.
3. **What does not count:** a result from another commit; a host-only result for a Simulator row; a screenshot not produced by the named test or command; a number typed from memory. A gate that was not run has not passed (ADR-004 Ruling 2). That <span title="What keeps an idea below the top: the cap that applies to it now.">holds</span> when pacing pauses work too. The Investors called that pause intended (2026-10-26 20:39), and it buys no extension.
4. **Test-count floors, from 40dbda23:** `git grep -h "func test"` gives 113 in pywidget/ios/Tests and 5 in pywidget/ios/UITests. Host suites at 22:3x: examples 92, widgets 32, pro_flags 38 (`run_host.py`). At the alpha commit, each count must be at or above its floor, with 0 failures and 0 skips. The one exception is a test removed under a dated board note, written before 2026-10-30 23:59, that says why.
5. **No crash, anywhere in the run.** The run window must produce no new `.ips` report in `~/Library/Logs/DiagnosticReports/` whose name starts with the app's or the widget extension's executable name, and no "crashed" line in any xc.sh summary. One crash fails the alpha, whichever row it falls in (Tenet 4).
6. **Changing a rule.** A rule here changes only by a dated chair line. That line applies only to rows whose evidence has not landed, and it says what changed and why. No rule changes after the run starts.

Simulator destination for every row: `-project PyWidget.xcodeproj -scheme PyWidget -destination "platform=iOS Simulator,name=iPhone 17e"` (written `$SIM` below), run from pywidget/ios through `tools/xc.sh`.

## 5. Chair ruling: a broken pro-flags.json leaves packages importable (Pernille's question, CONTRACT s4)

**Confirmed, with one condition.** The closed state stays as CONTRACT s4 writes it: no product id, no paywall rows, every premade locked (for entitled users too), Pro themes hidden, and packages unlocked.

Why. Running your own code is never paywalled (PROPOSAL-001 s4; memo s3). A configuration fault must never turn `import numpy` into an error in a script that worked yesterday. A paywall that fails open on packages costs us, at most, a free unlock in case C1. A paywall that fails closed on packages breaks a user's script with no way for them to fix it. The cost is also bounded: the file is a resource in the signed bundle (CONTRACT s2), so it cannot change after review, and the only way a broken file reaches a user is a build check that did not run.

The condition makes that impossible: **the check runs in the build, not only on the host.** T-0031 adds a build phase that runs `python3 pywidget/runtime/pro_flags.py` on the file being copied into both targets, and that fails the build on any error. A7's "bundled file resolves valid" assert runs in every test run. With both in place, the closed state is a reader's safety net and can never be a shipping state. That is also why I accept its harsher half, premades locked for a paying user. It can only happen in a build our own check refused.

Nothing else in the contract changes. Idris may implement `closed_state()` as written.
