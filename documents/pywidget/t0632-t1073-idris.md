Verdict: **PASS with fixes** (one fix line, T-1111)

## What the line asked (T-0632, from T-0414 (a), ADR-003 s3.6 item 4)

(1) Measure the stdlib's cross-run leak (a user's random.py bound by tempfile, two copies next run) with a host probe
and choose a rule. (2) Decide with Maren whether the console says when a file beside a script is passed over, and in
what words.

Both are done on paper. (1): the probe is in the ADR correction and in `StdlibFirstTests`; the rule (a name the
shipped stdlib holds resolves from the stdlib's own sys.path entries, ahead of app_packages and the script's folder;
stripped names fall through) is built in `_BundledFirst.find_spec` (runner.py:387-395). (2): Maren decided yes
(console-words.md:40-93), and `runner._NOTE` carries her words exactly. The note itself is built but off.

## What ran (host, foreground)

- `tests/bridge/test_runner_t0632.py`: 23 tests OK on 3.9.6 and 3.13.
- All of `pywidget/tests/bridge` (`unittest discover`): 261 tests, OK on 3.13, OK (skipped=6) on 3.9.6.
- Seeded mutants, each in a copy of App/Runtime through `PW_RUNTIME_DIR` (the tracked file never touched), against
  test_runner_t0632 + test_runner (66 tests), 3.13. Killed 8 of 11: no stdlib branch; site-packages kept in the
  stdlib path; zip home taken as the zip; a self-import counted; local imports not followed; note on by default
  (<span title="A test written in advance. If it fires, we drop the idea.">kills</span> NoteOffByDefaultTests and CrossRunResolutionTests:628); finder installed only with app_packages on; note in
  every context. Survived 3, below (F2, I1).
- Probe, before and after: a folder with `secrets.py` (`API_KEY = 'k'`) and `main.py`
  (`import secrets; print(secrets.API_KEY)`), one console file run. Runner at 9375dfc5^ (17108b8e): stdout `k`,
  status ok. Runner at acd59eeb, app defaults: the run ends in `AttributeError: module 'secrets' has no attribute 'API_KEY'` at main.py:2, nothing on stderr. Same runner
  with `passed_over_note: true`: stderr first carries "secrets.py in this folder isn't imported as secrets: Python's
  own secrets module is used instead. To use yours, rename it and import the new name."
- Read `_stdlib_path` against the app's layout (PythonRuntime.swift sets only `home`; the stdlib entries are
  python/lib/python3XX.zip, python/lib/python3.X, its lib-dynload; site-packages dropped by name). The Runtime
  folder and app_packages sit outside python/lib, so neither is taken as stdlib. No Runtime module has a stdlib name.

## Findings

### F1, Medium: the rule ships, the sentence that explains it does not, and no row turns it on

runner.py:289 (`_CFG["passed_over_note"] = cfg.get("passed_over_note") is True`) and runner.py:1197. The app sends
no such key (no Swift file names it), so the note is off in every build. T-0414 passed over the bundled top-level
names; 9375dfc5 adds every shipped stdlib name (290 on 3.13), and they include names a person writing a widget
picks for a helper file: `secrets.py`, `calendar.py`, `email.py`, `queue.py`, `token.py`, `code.py`, `types.py`.

Failure: a person keeps an API key in `secrets.py` beside `main.py` and writes `import secrets`. Before this commit
the run printed the key's value; now it stops with an AttributeError on `secrets.API_KEY` and nothing says why.
Maren decided on 2026-11-02 that the console says so; both the doc (console-words.md:37, :93) and the commit message
call the switch a follow-up row, and there is no such row on the board.

Fix (T-1111): change the one assertion at tests/bridge/test_runner.py:628 to expect the line, turn the note on for
the app <span title="One numbered piece of research into one area of ideas. Each lane has its own file.">lane</span> (the bootstrap default, or the key from the app's bootstrap config), and run the bridge suite on 3.9
and 3.13. Before lane-landed code goes to TestFlight.

### F2, Low: two mutants of the note survive

- runner.py:408, `passes_over` without its `sys.builtin_module_names` / `FrozenImporter` test: every test still
  passes. A user's `time.py` or `itertools.py` (builtins on 3.13: the folder is never reached) would then get no
  line, since the stdlib path holds no file for them. No test uses a builtin name.
- runner.py:528, `not node.level` removed (relative imports counted): every test still passes. A folder package
  whose `__init__.py` says `from .random import roll` would then draw a false note for a `random.py` beside the
  script. `test_silent_for_own_names_relative_imports_and_unparsable_files` does not use a passed-over name in its
  relative import.

Fix: two cases in test_runner_t0632.py, folded into T-1111.

### I1, Info: the `_S["main_file"] is not None` guard (runner.py:1198) is not what keeps buffer runs silent

With it replaced by `True`, every test passes: an editor buffer's path is `<editor:name>`, `os.path.dirname` gives
`""`, `os.listdir("")` raises, and runner.py:544's `except Exception` swallows it. The behaviour is the one Maren
asked for; the guard is belt and braces. No change.

### I2, Info: stale "until Maren signs"

console-words.md:3 ("not approved ... nothing visible ships until she signs the words"), runner.py:287-288, and
test_runner_t0632.py:12-13 and :171 still say the words wait for Maren. Her decision is in the same doc (:40). Update
with T-1111.

### I3, Info: a name both stdlib and bundled, stripped from the stdlib

`find_spec` (runner.py:390-393) returns the stdlib branch's None for such a name and never tries app_packages, so
the script's folder would win again. No package in pywidget/packages/manifest.toml has a stdlib name today. No change.
