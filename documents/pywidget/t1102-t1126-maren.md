Verdict: PASS with two fixes (F1, F2) and two notes. Read from the commit and the sources at HEAD, not Odalys's notes.

Ran: `python3 tools/premade_catalog.py --check` -> "catalog ok"; `python3 pywidget/tests/widgets/test_premade_catalog.py` -> 9 tests OK.

## The five checks

1. Entries and families: PASS. 12 ids equal pro-flags.json `premades`, in its order. Each entry's families equal the module's FAMILIES (5/5/6/4/4/4/4/4/5/4/4/3 families), each bundled tree's `views` keys equal the claimed families (script, 12 of 12, no extras or gaps). stale_after matches the modules: steps 3600, distance 1800, altitude 1800, storage 21600, github 2700; the other seven null. Matches s5.9 detail sheet (every claimed family).
2. Captions and uses: they match draw_gallery ABOUT (read by `ast`, so they cannot drift). They are NOT in creative/approved.md (it <span title="What keeps an idea below the top: the cap that applies to it now.">holds</span> no gallery copy; s9.11 itself says "Every one is DRAFT <span title="Commandment 51: the Investors approve every visual before it ships.">C51</span>"). They need C51 approval before release; so does `empty_line` ("No data yet, so this shows sample data."). See F1.
3. empty_case: PASS against code. True set (countdown No events, sun No place set, distance No saved places, habits No habits yet, shortcuts No shortcuts, clocks No cities, github No repository) each has a notice in its draw. False set: steps, altitude, storage, progress, quote have none for missing user data. Note N1: altitude "No altitude yet" and distance "No location yet" are no-fix states, covered by s5.9 states 3 and 4, so false is right for altitude; correct as is.
3b. The set is a hand list in the tool (EMPTY_CASE). The test pins it, but nothing ties it to the code, so a premade that gains or loses a notice stays green. See F2.
4. No tier: PASS. No tier in any entry; the top-level `tiers` key is a note string only. Test `test_no_tier_anywhere` guards it. The key invites a reader to expect data; harmless.
5. CATALOG.md for Idris: mostly enough (keys, order, tree reading, clock, what is left out). Gaps in F3.

## Fix lines
- F1 (C51): captions, uses and `empty_line` in catalog.json are DRAFT strings; put them to the Investors in the next copy card with s9.11, and mark the catalog as DRAFT until approved.
- F2: derive or check EMPTY_CASE against each premade's code (a test that runs every premade with empty inputs and asserts a notice), instead of a hand-listed set.
- F3: CATALOG.md must say that `trees` point into tests/widgets/fixtures, which the app does not bundle: name the bundled resource path or a copy step Idris can build from; list the `st.sample`, `st.empty` and caption strings the gallery also needs, and which s9.11 ids they are (it cites `about.*` ids the file does not carry).

## Notes
- N1: `--check` goes red on a changed premade (family, name, stale_after, ABOUT) because it rebuilds; the two mutants cover ids and families only.
