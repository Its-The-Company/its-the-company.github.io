**Verdict: PASS.** Code read from the commit, not from the notes. No fix needed before T-0191 or T-0657 build on it. Two Info items.

## Measured
1. `swift test --filter "GalleryTileRuleTests|SettingsProRowRuleTests"` in pywidget/ios/Core, host, foreground: 37 run (20 gallery, 17 Pro row), 0 failures.
2. Full `swift test` in the same tree: one process abort (signal 6) in LaneGuardTests (lock file test), which is not T-1103 code; both T-1103 suites pass alone. Not chased. Another agent's <span title="One numbered piece of research into one area of ideas. Each lane has its own file.">lane</span> files may have been mid-write; rerun at quiet.
3. Mutants file: 41 entries (matches the claim). My own mutant, not in the file: `mayPreview: true` changed to `!locked` in `actions`. Killed by testActionsFollowTheLockAloneInEveryState (line 144). File restored by git checkout; `git status` clean for it.

## Checked against the spec
1. **9.4, seven rows, first match wins.** `state()` tests in order: loading (over 300 ms, strict), failed, permission needed (`!locked && notAsked`), declined, offline, empty, live. Matches rows 1 to 7. The fallthrough (no run, or 300 ms or under) returns Loading with `showsSpinner` false, so no eighth case. Matches "no flash under 300 ms".
2. **Locked tile (T-0901).** `actions(locked:)` gives `mayAdd` and `mayOpenSource` as `!locked`, `mayPreview` always true, independent of state. A locked tile previews with no add and no src in every state; the test covers all state and run combinations.
3. **Tier only from the flag file.** The rule takes `locked: Bool` and has no premade id, no tier list, no flag read. Real source is `ProGates.isPremadeLocked` (ProFlags.swift:163: config nil gives locked, `freePremades[id] != true && !unlocked`). Nothing hard-coded.
4. **Refund.** A refunded Pro premade cannot reach add: refund makes `ProStore.isEntitled` false (ProStoreTests.swift:238-243, StoreKit-session test), `unlocked` false, `isPremadeLocked` true, so `mayAdd` false on the next ask. The rule is stateless, so it can't hold a stale grant. The caller must re-ask `isPremadeLocked` when Transaction.updates fires (see F1).
5. **10.2.** Rows: C3 gives no Pro group and no Restore; Restore in every state while for sale; detail off, on, pending; not-read-yet empty and outranks both; entitled outranks pending; refund back to off (entitled false); restoring disables and clears footer; footer restored, none, failed; cancelled shows nothing; unavailable and failed show `set.restore.failed`; offline restore ends in failed. String ids match the spec (test pins them).

## Findings
- **F1 (Info).** The rule is only as fresh as the `locked` it is handed. T-0191 must recompute `isPremadeLocked(id)` on each tile when the entitlement changes (including a refund while the gallery is open), not cache it per tile. Nothing to fix in T-1103; T-0191's review should look for it.
- **F2 (Info).** Header decision 3 and the spec hook say the caller must pass `.notRun` while a grant is not asked or declined. The rule cannot enforce it: a caller that passes `.failed` with `.notAsked` gets Failed and hides Allow. Documented in the spec hook; worth a test at T-0191's call site.
- The files reach the app target only after an xcodegen regen (noted on T-0191 and T-0657). Not run here; the Simulator slot is held.

No fix lines needed.
