## Verdict: PASS with 3 findings (none blocks; F1 and F2 are the ones to fix)

Run: `python3 pywidget/tests/run_host.py --both escape` -> py3.9.6 and py3.13.18 each 12 tests, 1 expected failure, 0 failed suites (n=2 interpreters, 24 tests).
Own mutant (n=1): plant an empty `_ctypes.pyc` at the stdlib root after the cut -> 3 tests fail (E2 file scan, E2 cut-check, E1/E2 import path as built); killed. Reverted, stdlib_cut.py clean in git.

## Checked
1. L12 s12 has 5 clauses; cases.json E1-E5 match them word for word, and `test_one_case_per_clause` fails if the paragraph moves. Pass (n=5).
2. Denylist: corpus keeps its own copy and a test pins it equal to stdlib_cut.py's DENY_EXACT/DENY_PREFIX. A cut that forgets an entry is caught twice. Pass.
3. Import cases not vacuous: a test requires the uncut stdlib to <span title="What keeps an idea below the top: the cap that applies to it now.">hold</span> every denylist name and some `_test*` and `xx*` names (16 names with those prefixes in lib-dynload today), and `ESCAPE_NO_CUT=1` turns the suite red by design. Pass.
4. E4 is listed for T-0043's Simulator run, not faked; a test pins that. Pass. E5 renderer half is listed too.
5. E5 on the validator: accepted case passes, refusal case is an expectedFailure. It cannot silently pass: when T-1134 lands the decorator must go (unittest counts an unexpected success as a failure from 3.4 on; I did not test that here, see F3).

## Findings
F1 (Medium). `escape_mutants.json` has no runner. Nothing in tools/ or the tests reads it (grep, n=0 hits), so "8 mutants killed" cannot be reproduced from the commit; I could only replay by hand. Fix: wire it into tools/mutants.py (or a small `tests/escape/run_mutants.py`) so it runs and prints killed/total.
F2 (Low). E1 and E3 test file presence through FileFinders, not the importer. Modules compiled into libpython (builtin) or frozen are invisible to it; the host's own `xxsubtype` is builtin here, though the iOS slice ships it as an extension (verified present in lib-dynload, so it is covered today). Fix: add a note in cases.json that a builtin/frozen `_ctypes` is out of scope, and have the Simulator half (T-0043) run a real `import ctypes` in the built app.
F3 (Low). The expectedFailure for E5 does not say who flips it. Fix: have T-1134's done-note require removing the decorator; add that to the T-1134 line.

No case marked passing was found that cannot fail: E1, E2, E3 each died under a seeded cut or my planted file; the accepted-Link case would fail if validate rejected pywidget:// links.
