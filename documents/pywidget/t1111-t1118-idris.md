## Findings

### I1, Info: the widget-lane half of the gate is not tested

runner.py:1197. Removing `and _CFG.get("lane") != "widget"` passes every test (M1). It is a second lock: the
extension sends only `context: .widget` (ExtensionLane.swift:216), and `context == "app"` already stops the line,
which M6 shows is tested. Failure scenario: only if a later change runs a context `app` request in the extension
lane would the line be written, into an extension stderr nobody reads. No user sees it today. No row; a one-case
test is cheap if someone is in the file.

### I2, Info: any value but JSON false turns the line on

runner.py:289. `"false"` (a string) or `0` from a config leaves the line on. That is the letter of the decision
("on unless the key is false"), and the app sends no key at all. Failure scenario: a later Swift setting that
writes the key as a string would not turn the line off. No change.

## Not covered

No Simulator or device run (the Xcode slot was held). The device stdlib path is the zip layout, which
`StdlibPathTests` covers on the host; the console line's rendering in the app is not seen in this review.
