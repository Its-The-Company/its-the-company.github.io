## T-1226 (Pernille): RatingFactsLedgerTests flake

Read only; no Xcode run (T-1116 holds this lane off the Mac mini's slot).

- The cause and fix agree. `RatingFactsLedger.encoded()` is `JSONEncoder().encode(self)` with no `.sortedKeys`
  (`pywidget/ios/App/RatingFactsLedger.swift:146`). The old test compared stored bytes with a second encode. The new
  test encodes once and compares against that value. Nothing is written while locked, so the stored bytes are the
  first encode, and the assertion is exact.
- The landed test patch is byte-identical to the lane commit 6d804140d (same diff hash). Her memory names 6d804140,
  the lane hash; the landed hash is 3c4e530e6. Info only.
- Production never compares two encodes: `RatingFactsStore.update` writes and `read` decodes. The varying key order
  is not a product defect. Info: `.sortedKeys` would make it deterministic; not needed.
- The other byte comparison in the file (`testAnUnreadableFileLoadsAsAskedAndIsNotOverwritten`, :280-293) already
  compares against one stored `bytes`. Safe.
- **F2 (Low, test hygiene).** Each test suite name is a fresh UUID, and `removePersistentDomain` leaves an empty plist
  behind (her own memory says so). Every host `swift test` run therefore adds two files to ~/Library/Preferences,
  without bound. 414 older ones from the t1149-/t1164- names are already there. Her memory says the delete was
  refused (T-0848). That open thread lives only in her memory, not on the board. Line T-1393.
- Memory commit 192c5777f: MEMORY.md is 3,939 bytes, under 4 KB; the older lines moved to the archive verbatim.
