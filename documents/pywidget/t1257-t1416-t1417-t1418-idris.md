## T-1257

The change: `bridge_driver._seed` gets a `stop_in` list. When a seeded `slow` function is named in it, its first call starts a `threading.Timer(0.1, fake.stop(run_id))` and then does its seeded sleep. The test swaps `stop_after=0.6` for `stop_in=["_flush_streams"]`, keeping `slow={"_flush_streams": 1.2}`.

Read against the runner: `_flush_streams` is reached only through `widget_tree.emit` (`flush()` after the size check, widget_tree.py:203), so the first call is the tree flush. `fired=[]` is a default bound when each `make` is defined, so it is fresh per seeded function per step. `fake.stop` refuses a run id that is not the current run, so a late timer cannot spill into the next step. The test still asserts `stop_dt` is not None, so a Stop that never arrives fails rather than passing empty.

Mutants, run in a scratch copy (/tmp, `PW_RUNTIME_DIR` not needed: whole pywidget/tests, python, python-stubs, Runtime and bridge-contract.md copied), test `test_a_stop_during_the_tree_flush_keeps_the_finished_render` only, on python 3.9.6 and 3.13:

| Mutant | 3.9.6 | 3.13 |
|---|---|---|
| M1: `user_on()` before `flush()` in `widget_tree.emit` (repeats on during the flush: the T-0426 bug) | killed: `'interrupted' != 'ok'` x2 | killed |
| M2: the `stop_in` timer removed | killed: "the seeded Stop was requested" x2 | killed |
| M3: `time.sleep(2.5)` at the top of the fixture (slow user code before render, the flake's shape) | survives, as it should | survives |
| Control: M3 against the old test (0460fe8cb^, `stop_after=0.6`) | **red**: `'interrupted' != 'ok'` x2 | **red** |

So the old test reproduces the flake when the run before render is slow, the new one does not, and the new one still goes red on the real bug (M1) and on a Stop that never comes (M2). The fix removes the wall clock without hiding a failure.

Not filed (notes only):
- A `stop_in` name that is not also in `slow` does nothing, silently. This test would catch it (`stop_dt` None); a future test that does not assert `stop_dt` would not. `_seed`'s docstring and the test module's header still describe `stop_after` only.
- The 0.1 s timer is still a thread timer; a scheduling delay over about 1.1 s would put the Stop after the flush (still quiet, so still a fair pass) or after the run (red, loudly). Far smaller window than an import.
- The <span title="One numbered piece of research into one area of ideas. Each lane has its own file.">lane</span> record 2544563e3 cites e9e5aafbd; main has 0460fe8cb. Same patch-id (1083c482); the board line gives the main hash.
