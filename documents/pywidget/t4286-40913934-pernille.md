## Verdict: PASS with findings

The probe stays out of every shipping build. All of FontProbe is inside `#if PYWIDGET_TESTER_PRO`; outside it the two
calls are empty inline functions, and the Release extension binary I built carries none of its strings. The font is
copied by a script phase that reads the same condition from SWIFT_ACTIVE_COMPILATION_CONDITIONS, removes any stale copy
first, and is proven both ways by ScriptTests; two mutants of it go red. The condition itself is held to Debug and
`upload.sh --internal` by check_tester_pro.py at build time and by the mark scan on every archive, unchanged by this work.
An internal TestFlight build carries 329 KB more; nothing reaches App Review or the App Store.

The licence allows it. Pacifico is SIL OFL 1.1. Bundling with software and redistribution are allowed (condition 2) if
each copy carries the copyright notice and the licence, which may sit in the font's machine-readable metadata. The file's
name table carries both, unmodified; I read them. There is no Reserved Font Name, nothing is renamed, and the font is not
sold by itself. It is a human-drawn face (Vernon Adams, 2011), so Commandment 6 is met, and the log/assets.md row is
there. SOURCE.md already says it needs a components.json row and an Acknowledgements entry before it ships as a product
font; that is right and should hold.

The code is careful. The read-back by PostScript name cannot pass on a fallback face, a non-font .ttf and an empty folder
are never a success, and the unit tests check each of those. The findings are about what the probe can tell on a phone
(M1), one guard test the second commit weakened (L1), and a rerun hazard in the UI check (L2).

## Findings

### M1. The face is registered where the timeline is built, not where the widget is drawn, and the result cannot tell them apart (T-4776)

- Where: `ios/Widget/PyWidget.swift:64` and `:87` (`FontProbe.prepare` in `drawn()`, reached from `timeline` and
  `snapshot`); `ios/Shared/FontProbe.swift:156-170` (once per process, result written once).
- Scope .process lasts as long as the extension process. The probe registers only when the provider builds a timeline or
  a snapshot. If WidgetKit draws an entry it already holds in a new extension process without asking the provider first
  (after the process was ended, after a restart, or for a Lock Screen or StandBy rendering mode), nothing registers the
  face in that process, and the line draws in the fallback face. I cannot show from Apple's pages that WidgetKit does
  this. But the phone check exists to test exactly these cases (Lock Screen, StandBy, after a restart), and
  probe-result.json records only the first registration. A fallback face on the phone would then read as "an imported
  font does not draw in a widget", when it may only mean "registered in the wrong place". That would be a wrong answer
  to the question T-4271 asked.
- Fix: also call `FontProbe.prepare` where the tree is drawn (the entry view's body, on the custom-font path only; it is
  once per process and costs nothing after). Record in the result which caller registered it (provider or view), and
  write one line per process to the log, not only the first. Then a fallback on the phone can be told apart from a
  registration that never ran in that process.

### L1. The tester-flag parser no longer sees a Release setting written as a YAML block scalar (T-4777)

- Where: `tests/widgets/test_tester_pro_flag.py:87-111` (`_settings_paths`, the block-scalar skip at :93-102).
- 4091393426 skips the body of every block scalar, so the probe phase's `script: |` stops counting. It does not check
  which key opened the block. A setting such as
  `SWIFT_ACTIVE_COMPILATION_CONDITIONS: >-` / `PYWIDGET_TESTER_PRO` (or `OTHER_SWIFT_FLAGS: |` / `-DPYWIDGET_TESTER_PRO`)
  planted under the project-level Release config is now invisible: `test_no_release_setting_names_it` would stay green.
  The parent's parser finds both (run above). check_tester_pro.py at build time and the archive mark scan still catch
  such a build, so nothing ships from this. But this test is the second layer of a Guideline 3.1.1 guard, and it got
  weaker.
- Fix: skip a block body only when the key that opened it is `script` (or `shell`/`inputFileListPaths`-style phase keys,
  if any are added later). Add a planted-block test beside `test_the_parser_sees_a_planted_release_line`: a `>-`
  SWIFT_ACTIVE_COMPILATION_CONDITIONS under Release must be found.

### L2. The UI check fails on a second run while the widget extension is still alive (T-4778)

- Where: `ios/UITests/WidgetKitCheckTests.swift:314-315` (deletes fonts/probe-result.json) and `:349` (reads it);
  `ios/Shared/FontProbe.swift:159-160` (`done` is per process; the file is written once).
- The test removes the result file and expects the extension to write it again. If the extension process from an earlier
  run of this test (or any earlier custom-font draw) is still alive in the same Simulator boot, `done` is already true
  and the file is never written, so `Data(contentsOf: result)` throws. It is a measurement test (WK_TREES), so a false red
  costs a rerun, not a release. It will catch whoever reruns it to get shots.
- Fix: in `prepare`, when `done` is set but the result file is missing, write the kept result again; or have the test
  end the extension before it starts (the other WidgetKit checks' helper, if there is one) and say so in its doc comment.

### Notes (no work)

- N1. A build that sets the flag only through OTHER_SWIFT_FLAGS (`-DPYWIDGET_TESTER_PRO`) compiles the probe, but the
  phase (project.yml:355) reads only SWIFT_ACTIVE_COMPILATION_CONDITIONS and copies no font. It fails closed: the probe
  reports no files. No such build exists today (upload.sh sets the condition).
- N2. `prepare` sets `done` before it registers, so an empty fonts/ is recorded once per process and not tried again.
  In the probe's flow the app seeds fonts/ at launch (PyWidgetApp.swift:23) before any run can write a custom-font tree,
  so this is not reached.
- N3. The Release app bundle was not checked for FontProbe/ by a finished build (see What I ran). The phase's Release
  behaviour rests on ScriptTests and the mutants above. When the Legal links check is green, one Release build and
  `ls PyWidget.app/FontProbe` closes it.
