## Findings

### M1 (Medium): `--test` and the page leave out two gate-only checks that hold the ladder

`gate_session_build.sh --test` now runs SettingsUITests' gated row, MeasurementExportTests and GatePremadeTests. Two
more tests have a `#if PYWIDGET_LANE_GATE` half about the ladder and still run it only when someone puts the
condition on by hand, the same gap as review L2 one file over:

- `ExtensionLaneTests.swift:1295-1303`, `testOnlyTheGateBuildExemptsItsOwnPremades` (T-4643): `sizeMoveExempt` is
  exactly GatePremade's ids in the gate build. If that breaks, every rung moves to the app after its first widget run,
  and the phone session (T-4536) gets one widget reading per rung instead of one per reload. The plain unit target runs
  only the `#else` half (`sizeMoveExempt == []`), so it stays green.
- `WidgetPlacementTests.swift:11-19` (`laneTail`, `gateTail`), read by the picker tests at `:50`, `:58` and `:65`
  (the picker lists overrun and the 12 rungs after every shipping premade, in any Pro state), and `:173-180` (each
  rung's picker title is GatePremade's and its own `make()` line's, and no rung is in the title table).

`gate-session-build.md` ("What holds the ladder in the gate build ... Three tests") names neither, so the page reads
as the whole list when it is not.
**Fix (Idris, T-5021):** add `-only-testing:PyWidgetTests/ExtensionLaneTests/testOnlyTheGateBuildExemptsItsOwnPremades` and
`-only-testing:PyWidgetTests/WidgetPlacementTests` (a unit class; four of its tests read the gate tail) to `--test`,
name them on the page, and run `--test` once with all of them.

### L1 (Low): the preview half of the read-and-draw test cannot fail

`test_gate_premade.py:480-484`. The preview runs on the same folder the real run just wrote, and `snapshot` compares
file contents only. A preview that wrongly opened the real `Store` would climb to 10 MiB and write `lane-held` = "10"
again, the same bytes, so the snapshot is equal. Mutant (e) shows it: with `open_store` ignoring `FILE_KEY`, the test
passes. `assertIsNone(k.MemoryStore({}).folder)` checks a constructor, not the run. Overrun's twin test
(`:258-266`) does it right: an empty folder, then `os.listdir(folder) == []`.
**Fix (Idris, T-5022):** run the preview with `OPENER` on a second, empty temp folder and assert it stays empty; drop the
`MemoryStore({}).folder` line. Small, same place: the test inserts the tests folder into `sys.path` at `:458` and
never takes it out; `premade_support` is already loaded by `setUpClass` (`:279`), so
`sys.modules["premade_support"].doc_errors` needs no path change.

### L2 (Low): the phone request's own line still reads as before, and the notes miss the 12 rungs

- `ops/board.md:110` (T-4536) still says "from T-4282 (cdfacacc4c)", "place Ladder 1 to 7" and "run rows and memory
  figures, no personal data". The corrected sentence is only in `board_notes/T-4536.md:2`. `board_tick.py` has no
  body edit, so a note is the tool's way, but whoever opens the <span title="A GitHub issue asking the Investors for something that is blocking work.">Urgent Request</span> copies the steps from the line.
- Since T-4643 (98b2f14988, on main, before this commit) the gate build has 12 rungs, not 7: memory rungs 1-9 and
  time rungs 10-12. The T-4536 line asks for "Ladder 1 to 7", which would leave out every time rung and two memory
  rungs. The T-2943 note this commit edits (`board_notes/T-2943.md:2`) now reads "88ba326d54, on main ... ladder1..7";
  the next gate upload must carry 98b2f14988's ladder, `ladder1..12`.
- `board_notes/T-4282.md:2`: "what landed on main is 88ba326d54, T-4644" reads as if T-4644 landed it. "(corrected
  in T-4644)" says what is meant.
**Fix (Idris, T-5023):** one note each on T-4536 and T-2943 that the request places Ladder 1 to 12 and Memory overrun, and
that the build must carry 98b2f14988; or close T-4536 and add it again with the corrected steps, hash and sentence,
which is cleaner, since the request is built from the line.
