## Verdict: PASS with findings

The rule is right. `_tap_count(node, family)` (`python/pywidget_ui/__init__.py:2252-2271`) passes the family down
every path (`c`, `alt`, props and modifier views), and only a When whose `env` is `family` uses it: a list `is`
means any of, a plain string means equal, and anything else (missing, a number) takes `otherwise`. That is exactly
`TreeRules.whenHolds` (`ios/Shared/TreeRules.swift:163-167`, called from `TreeView.swift:322-329`): `is` as a list or
one value, membership, and `otherwise` when nothing matches. Every other env still counts its larger branch, and
a call with no family keeps the old maximum. The lint passes the family at `__init__.py:2137`. My probed tree now
prints nothing, and a family When whose drawn branch is over the cap still prints one line for that family only.
The fixture case gives systemSmall 1 and every other family 3, which is what the renderer draws, and the second
case keeps a colorScheme When at its larger branch. API.md's `Widget.document` row (`python/pywidget_ui/API.md:155`)
says what the code does.

What is left is in the tests, not the code. The core rule is pinned, but its spread into nested trees and the
plain-string form is not, and the fixture that Swift is to read has neither (L1). Nothing here holds TestFlight.

## Findings

### L1 (Low): nested family Whens, a plain-string `is` and a missing branch are not pinned

- Where: `tests/dsl/test_actions_t4550.py:258-286` and `tests/fixtures/widget-button-caps.json:28-38`. Every family
  When in the tests is the tree's root, and every `is` is a list.
- The failure, by mutant: if `_tap_count` stops passing the family to a When's or a stack's children (mutant 4),
  to prop and modifier views (6), or stops matching a plain-string `is` (7), all 318 dsl tests still pass. Yet
  the usual shape is a When inside a VStack beside a title, and `ui.When("family", "systemMedium", ...)` is the
  documented one-value form. Mutant 11 (an empty matching branch counting the other) also survives; a family When
  with no `otherwise` is the plain way to add buttons only in Medium.
- Why the fixture: it is the table step 6's Swift renderer test is to read (ADR-011 s3, "One fixture table drives
  the Python and Swift tests"). Cases that exist only in Python tests do not reach Swift, so the Swift count could
  differ on these shapes with both suites green.
- Also: the test reads `count.get(fam, count["*"])`, which needs `"*"` even when every family is named; the
  `about` text says `"*"` is "for the families not named". Say it is always present, or read it only when needed,
  so the Swift reader follows one rule.
- Fix: three fixture cases: a family When inside a VStack beside other Buttons; a family When with a plain-string
  `is`; a family When with no `alt` (count 0 in the families it misses). Each with per-family counts.

### L2 (Low): a code comment says Swift's tests read the fixture; none do yet

- Where: `python/pywidget_ui/__init__.py:2236-2238` ("... widget-button-caps.json, which Swift's tests read too").
  This line came with T-4550, not this commit, but the commit edits the rule beside it.
- `git grep widget-button-caps` finds the file only in this test, the comment and my earlier review. The renderer
  draws every Button today; the cap and its test are build step 6 (mine). The fixture's `about` says it rightly
  ("are to read").
- Fix: "which Swift's tests are to read (build step 6)", until that test exists.

## Not findings

- API.md's row still says "the widget draws the first that many and drops the rest". That is the renderer's
  promised behaviour in ADR-011 s3 and step 6, and the row is marked `proposed`; it is not this commit's text.
- The count is an upper bound for Whens on other envs (colorScheme, dynamicTypeSize and the rest), so a widget can
  still get a line for a branch it draws only in dark mode. That is the cautious count M1 asked to keep.
