Direction C, screens 2 and 3: the Builder and the editor

In direction C the finished thing is on the screen at every step. The Builder comes first on this page because C puts it first: the widget sits on a stage at the top and the blocks are large cards under it. The editor is the same project one tap away, through the Blocks and Code switch or through the round code button on a block. The sample Python and its module names are placeholders, not the app's API. Builder and Project are placeholder names.

The Builder, iPhone, 390 wide

What to look at:

  • The widget is at the top, at real size, and stays there while the blocks scroll under it. Direction A rests the preview at the bottom.
  • Choosing a block rings its part of the widget. A lights the block's Python lines; C lights the picture, and keeps the Python one tap away.
  • Blocks are cards 56 px high, tinted by kind: data, text, number, row. The chosen card opens in place with its settings.
  • Two ways to code, each one tap: the Blocks and Code switch for the whole file, and the round button on the chosen block for its own lines.
  • Inside a tool the tab bar gives way to one large button. 03's phone sketch keeps the tab bar; C does not.

The Builder, iPad

Three columns: the blocks to pick from as tiles, the widget's own blocks, and the stage with both sizes at real size. The Python the blocks produce sits under the stage, read only, with the chosen block's three lines lit and "Edit as code" beside it. "Your Python" is 03's custom block: a file the person wrote, shown as one block.

The editor, iPhone, 390 wide

What to look at:

  • The code is the approved editor: Quill in light, Lumen in dark, 15 px, nothing restyled. C changes what is around it.
  • Files are pills in a row that scrolls sideways. The line under them says which outputs use the open file.
  • The widget floats over the editor as a small live picture and redraws on each run. It can be dragged, and a tap opens the full preview. 03 has a sheet pulled up from the bottom; C departs here, and the cost is that the picture covers 98 by 98 px of the screen.
  • Run is one large button at the bottom, in the same place as "Add a block" in the Builder.

The editor, iPad

The same three columns as the Builder, so the switch moves nothing: files as cards on the left, the editor and console in the middle, the stage on the right. Under the stage, one card says which outputs read the open file and what the file touches.

Where these screens depart, and what they keep

  • Kept: the syntax themes, the editor and console grounds, the Blocks and Code switch, read-only generated Python with "Edit as code", hand-written code as one block, every approved colour. The full table is on screen 1.
  • Departs from the approved drawings: the editor sits on a rounded card with room around it, where the approved editor runs edge to edge. The file list is pills and cards, not a tree.
  • Departs from 03: no tab bar inside a tool on iPhone; a floating picture in place of the pull-up sheet; on iPad the Python sits under the stage, smaller, not beside the blocks.
  • New here and in no token file: the tile tints on block cards, one tint for each kind of block.
